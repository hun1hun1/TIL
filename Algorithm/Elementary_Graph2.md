## 위상 정렬

위상 정렬(Topological Sort)은 선후 관계가 있는 작업들을 가능한 순서로 나열하는 방법이다.

예를 들어 과목 B를 수강하기 전에 과목 A를 이수해야 한다면 다음 관계로 표현할 수 있다.

```
A → B
```

이 경우 가능한 순서에서는 A가 B보다 먼저 나와야 한다.

위상 정렬은 이러한 관계를 모두 만족하는 정점의 순서를 구한다.

### 방향 비순환 그래프

위상 정렬은 방향 비순환 그래프(Directed Acyclic Graph, DAG)에 대해 정의한다.

DAG는 다음 두 조건을 만족한다.

- 모든 간선에 방향이 있다.
- 방향을 따라 출발 정점으로 돌아오는 사이클이 없다.

예를 들어 다음 그래프는 DAG이다.

```
A → B → C
```

반면 다음 그래프에는 방향 사이클이 있다.

```
A → B → C
↑       │
└───────┘
```

이 그래프에서 A는 B보다 먼저, B는 C보다 먼저, C는 다시 A보다 먼저 나와야 한다.

세 조건을 동시에 만족하는 순서는 만들 수 없다.

자기 자신을 향하는 간선도 사이클이므로 위상 정렬을 방해한다.

### 위상 정렬의 정의

DAG G = (V, E)의 위상 정렬은 모든 정점을 한 줄로 나열한 순서이다.

이 순서는 모든 간선 (u, v)에 대해 다음 조건을 만족한다.

```
u가 v보다 먼저 나온다.
```

즉, 간선의 방향이 다음과 같다면 다음과 같다.

```
u → v
```

위상 순서에서 u는 v보다 앞에 있어야 한다.

정점들을 한 줄로 나열했을 때 모든 간선이 왼쪽에서 오른쪽을 향한다고 생각할 수 있다.

위상 정렬은 숫자의 크기를 기준으로 정렬하는 것이 아니다.

정점 사이의 선후 관계를 만족하도록 순서를 정하는 것이다.

서로 선후 관계가 없는 정점의 순서는 달라질 수 있으므로, 하나의 DAG에 여러 위상 순서가 존재할 수 있다.

### 위상 정렬 예제

다음 방향 그래프를 생각해 보자.

```
A → C → E
    ↑   ↑
B ──┘   │
│       │
└→ D ───┘
```

간선 집합은 다음과 같다.

$$
E=\{(A,C),(B,C),(B,D),(C,E),(D,E)\}
$$

정점 A와 B는 서로 직접적인 선후 관계가 없다.

정점 C는 A와 B 다음에 나와야 한다.

정점 E는 C와 D 다음에 나와야 한다.

가능한 위상 순서의 예시는 다음과 같다.

```
A, B, C, D, E
```

다음 순서도 가능하다.

```
B, D, A, C, E
```

두 순서 모두 모든 간선의 출발 정점이 도착 정점보다 먼저 나온다.

반면 다음 순서는 올바르지 않다.

```
A, C, B, D, E
```

간선 B → C가 있는데 C가 B보다 먼저 나오기 때문이다.

### DFS를 이용한 위상 정렬

DAG에서 DFS를 수행한 뒤 정점들을 종료 시간의 내림차순으로 나열하면 위상 순서를 얻는다.

```
TOPOLOGICAL-SORT(G)
    perform DFS(G)

    order = vertices sorted by decreasing finishing time

    return order
```

실제 구현에서는 종료 시간을 계산한 뒤 별도로 정렬할 필요가 없다.

정점의 DFS가 종료될 때마다 목록의 앞에 추가하면 된다.

```
TOPOLOGICAL-SORT(G)
    mark every vertex WHITE
    order = empty list

    for each vertex u in G.V
        if u.color == WHITE
            TOPOLOGICAL-VISIT(G, u, order)

    return order
```

```
TOPOLOGICAL-VISIT(G, u, order)
    u.color = GRAY

    for each v in G.Adj[u]
        if v.color == WHITE
            TOPOLOGICAL-VISIT(G, v, order)

    u.color = BLACK
    add u to the front of order
```

또는 종료된 정점을 배열의 뒤에 추가하고, 마지막에 배열을 뒤집어도 된다.

이 의사코드는 입력이 DAG라는 전제에서 동작한다.

입력에 사이클이 있을 수 있다면 별도의 사이클 검사를 추가해야 한다.

#### 실행 예제

앞의 그래프를 다음 인접 리스트로 표현한다.

```
A: C
B: C, D
C: E
D: E
E: 없음
```

전체 DFS의 정점 검사 순서는 A, B, C, D, E이고, 인접 리스트도 표시된 순서대로 검사한다고 하자.

| 정점 | 발견 시간 | 종료 시간 |
|---|---:|---:|
| A | 1 | 6 |
| B | 7 | 10 |
| C | 2 | 5 |
| D | 8 | 9 |
| E | 3 | 4 |

정점이 종료되는 순서는 다음과 같다.

```
E, C, A, D, B
```

이를 반대로 나열하면 다음 위상 순서를 얻는다.

```
B, D, A, C, E
```

모든 간선에 대해 출발 정점이 도착 정점보다 먼저 나온다.

### DFS 위상 정렬의 정당성

DAG의 임의의 간선 (u, v)를 생각해 보자.

DFS에서 u를 발견하여 간선 u → v를 검사할 때 v의 상태를 생각할 수 있다.

#### v가 WHITE인 경우

v는 아직 발견되지 않았다.

DFS는 u의 탐색을 잠시 중단하고 v를 먼저 탐색한다.

v와 v에서 이어지는 재귀 탐색이 끝난 다음에야 u의 탐색을 마칠 수 있다.

따라서 다음이 성립한다.

$$
v.f<u.f
$$

#### v가 BLACK인 경우

v의 탐색은 이미 끝났다.

u는 아직 탐색 중이므로 이 경우에도 다음이 성립한다.

$$
v.f<u.f
$$

#### v가 GRAY인 경우

v가 GRAY라면 현재 DFS 경로에서 v가 u의 조상이다.

그런데 u → v 간선도 존재하므로 방향 사이클이 만들어진다.

입력이 DAG라는 가정에 모순되므로 이 경우는 발생하지 않는다.

따라서 DAG의 모든 간선 u → v에 대해 다음이 성립한다.

$$
u.f>v.f
$$

정점을 종료 시간의 내림차순으로 나열하면 모든 간선의 출발 정점이 도착 정점보다 먼저 나오므로 위상 순서가 된다.

### 사이클 검사

방향 그래프에서 DFS가 GRAY 정점으로 향하는 간선을 발견하면 역방향 간선이다.

이 간선은 현재 DFS 경로를 따라 조상으로 돌아가므로 방향 사이클이 존재한다.

따라서 위상 정렬을 수행하기 전에 또는 수행하는 동안 이 조건을 검사할 수 있다.

```
for each v in G.Adj[u]
    if v.color == WHITE
        VISIT(v)
    else if v.color == GRAY
        report "사이클 존재"
```

사이클이 있다면 위상 순서는 존재하지 않는다.

반대로 방향 그래프에 사이클이 없다면 DFS 종료 시간의 내림차순으로 위상 순서를 만들 수 있다.

따라서 다음이 성립한다.

```
방향 그래프에 위상 순서가 존재한다.
              ⇕
방향 그래프가 DAG이다.
```

### 시간 복잡도와 공간 복잡도

인접 리스트를 사용하면 DFS는 모든 정점과 간선을 한 번씩 검사한다.

종료된 정점을 배열에 추가한 뒤 마지막에 뒤집으면 위상 순서를 만들기 위한 시간도 O(|V|)이다.

따라서 전체 시간 복잡도는 다음과 같다.

$$
\Theta(|V|+|E|)
$$

색, 결과 순서, DFS 호출 스택을 위한 추가 공간은 다음과 같다.

$$
O(|V|)
$$

이는 그래프 자체의 저장 공간을 제외한 값이다.

## 강한 연결 요소

방향 그래프에서는 A에서 B로 갈 수 있어도 B에서 A로 돌아올 수 없는 경우가 있다.

강한 연결 요소는 양방향으로 도달할 수 있는 정점들을 묶은 것이다.

### 강한 연결 요소의 정의

방향 그래프가 강하게 연결되어 있다는 것은 임의의 두 정점 u와 v에 대해 다음이 모두 가능하다는 뜻이다.

- u에서 v로 도달할 수 있다.
- v에서 u로 도달할 수 있다.

방향 그래프 G = (V, E)의 강한 연결 요소(Strongly Connected Component, SCC)는 다음 조건을 만족하는 최대 정점 집합 C이다.

$$
C\subseteq V
$$

C에 속하는 모든 정점 u, v에 대해 다음 경로가 존재한다.

$$
u\leadsto v
\qquad\text{and}\qquad
v\leadsto u
$$

여기서 최대(Maximal)라는 것은 조건을 유지하면서 C에 다른 정점을 더 추가할 수 없다는 뜻이다.

가장 많은 정점을 포함하는 강한 연결 요소 하나만 찾는다는 뜻은 아니다.

정점 하나에서 자기 자신으로는 길이가 0인 경로로 도달할 수 있다.

따라서 다른 정점과 서로 도달할 수 없는 정점도 하나의 SCC가 된다.

### 강한 연결 요소 예제

다음 방향 그래프를 생각해 보자.

```
A → B → C → D ⇄ E → F
↑       │
└───────┘
```

정확한 간선은 다음과 같다.

```
A → B
B → C
C → A
C → D
D → E
E → D
E → F
```

A, B, C는 방향을 따라 서로 도달할 수 있다.

```
A → B → C → A
```

D와 E도 서로 도달할 수 있다.

```
D → E
E → D
```

F에서는 다른 정점으로 가는 간선이 없다.

따라서 SCC는 다음 세 개이다.

```
{A, B, C}
{D, E}
{F}
```

C에서 D로 갈 수 있지만, D에서 C로 돌아오는 경로는 없다.

따라서 두 집합은 같은 SCC가 아니다.

### 전치 그래프

방향 그래프 G의 전치 그래프(Transpose Graph) Gᵀ는 모든 간선의 방향을 반대로 바꾼 그래프이다.

$$
G^T=(V,E^T)
$$

$$
E^T=\{(v,u):(u,v)\in E\}
$$

예를 들어 원래 간선이 다음과 같다면 다음과 같다.

```
A → B
```

전치 그래프에서는 다음 간선이 된다.

```
B → A
```

원래 그래프의 모든 경로는 전치 그래프에서 방향이 반대인 경로가 된다.

따라서 원래 그래프에서 두 정점이 서로 도달 가능하면 전치 그래프에서도 서로 도달 가능하다.

결과적으로 G와 Gᵀ의 SCC 분할은 같다.

단, SCC 사이의 간선 방향은 반대가 된다.

### 요소 그래프

각 SCC를 하나의 정점으로 줄이고, 서로 다른 SCC 사이의 간선을 연결한 그래프를 요소 그래프(Component Graph)라고 한다.

앞의 예제에서 SCC를 다음과 같이 이름 붙이자.

```
X = {A, B, C}
Y = {D, E}
Z = {F}
```

그러면 요소 그래프는 다음과 같다.

```
X → Y → Z
```

요소 그래프에는 방향 사이클이 없다.

만약 서로 다른 SCC들이 사이클을 이룬다면, 그 사이클에 속한 모든 SCC의 정점은 서로 도달할 수 있다.

그러면 이들은 하나의 더 큰 SCC가 되어야 하므로 서로 다른 SCC라는 가정에 모순된다.

따라서 요소 그래프는 DAG이다.

## DFS를 이용한 강한 연결 요소 탐색

DFS를 두 번 사용하는 대표적인 방법으로 코사라주 알고리즘(Kosaraju's Algorithm)이 있다.

첫 번째 DFS에서 구한 종료 시간을 이용하여 두 번째 DFS의 시작 순서를 정한다.

### 알고리즘

```
STRONGLY-CONNECTED-COMPONENTS(G)
    perform DFS(G)
    record each vertex's finishing time

    GT = TRANSPOSE(G)

    mark every vertex WHITE in GT
    components = empty list

    for each vertex u in decreasing order of finishing time
        if u.color == WHITE
            component = empty list

            DFS-COLLECT(GT, u, component)

            append component to components

    return components
```

DFS-COLLECT는 전치 그래프에서 u로부터 도달할 수 있는 WHITE 정점들을 발견하여 component에 추가한다.

```
DFS-COLLECT(GT, u, component)
    u.color = GRAY
    append u to component

    for each v in GT.Adj[u]
        if v.color == WHITE
            DFS-COLLECT(GT, v, component)

    u.color = BLACK
```

두 번째 DFS에서 새로 시작한 탐색 하나가 하나의 SCC를 만든다.

첫 번째 DFS에서 정점이 종료될 때 배열에 추가해 두면, 두 번째 DFS에서 그 배열을 뒤에서부터 읽을 수 있다.

따라서 종료 시간을 기준으로 별도의 비교 정렬을 할 필요는 없다.

### 실행 예제

앞의 그래프를 인접 리스트로 나타내면 다음과 같다.

```
A: B
B: C
C: A, D
D: E
E: D, F
F: 없음
```

#### 첫 번째 DFS

정점 검사 순서가 A, B, C, D, E, F이고 각 인접 리스트도 표시된 순서라고 하자.

A에서 시작한 DFS는 다음 순서로 새로운 정점을 발견한다.

```
A → B → C → D → E → F
```

각 정점의 발견 시간과 종료 시간은 다음과 같다.

| 정점 | 발견 시간 | 종료 시간 |
|---|---:|---:|
| A | 1 | 12 |
| B | 2 | 11 |
| C | 3 | 10 |
| D | 4 | 9 |
| E | 5 | 8 |
| F | 6 | 7 |

종료 시간의 내림차순은 다음과 같다.

```
A, B, C, D, E, F
```

DFS 순서가 달라지면 개별 종료 시간과 이 순서도 달라질 수 있다.

#### 전치 그래프 구성

모든 간선의 방향을 바꾸면 다음 인접 리스트를 얻는다.

```
A: C
B: A
C: B
D: C, E
E: D
F: E
```

#### 두 번째 DFS

첫 번째 DFS의 종료 시간 내림차순인 A, B, C, D, E, F 순서로 정점을 검사한다.

먼저 A에서 전치 그래프의 DFS를 수행하면 다음 정점들을 발견한다.

```
A → C → B
```

첫 번째 SCC는 다음과 같다.

```
{A, B, C}
```

B와 C는 이미 발견되었으므로 건너뛴다.

다음 미발견 정점 D에서 탐색하면 E를 발견한다.

D에서 C로 향하는 전치 간선이 있지만 C는 이미 처리되었다.

두 번째 SCC는 다음과 같다.

```
{D, E}
```

마지막으로 F에서 새로운 탐색을 시작한다.

F에서 E로 향하는 간선이 있지만 E는 이미 처리되었다.

세 번째 SCC는 다음과 같다.

```
{F}
```

최종 결과는 다음과 같다.

$$
\{A,B,C\},\quad\{D,E\},\quad\{F\}
$$

### 알고리즘의 동작 원리

원래 그래프의 서로 다른 SCC C와 D 사이에 다음 간선이 있다고 하자.

```
C → D
```

한 SCC에 속한 정점들의 종료 시간 중 최댓값을 그 SCC의 종료 시간이라고 하자.

$$
f(C)=\max_{v\in C}v.f
$$

원래 그래프에서 전체 DFS를 수행하면 다음이 성립한다.

$$
f(C)>f(D)
$$

이를 두 경우로 생각할 수 있다.

1. C가 먼저 발견되면 C에서 D로 도달할 수 있으므로, D의 탐색이 끝난 뒤 C에서 시작된 탐색이 종료된다.

2. D가 먼저 발견되면 D에서는 C로 도달할 수 없다. 도달할 수 있다면 C와 D는 하나의 SCC가 되기 때문이다. 따라서 D의 탐색이 끝난 후 C가 발견되어 더 늦게 종료된다.

첫 번째 DFS의 종료 시간 내림차순으로 정점을 선택하면, 원래 요소 그래프에서 아직 처리하지 않은 요소들을 적절한 순서로 선택하게 된다.

전치 그래프에서는 SCC 사이의 간선 방향이 반대가 된다.

이미 처리한 SCC는 방문된 상태이므로 다시 들어가지 않는다.

또한 현재 SCC에서 아직 처리하지 않은 다른 SCC로 넘어갈 수 없도록 이 순서가 정해진다.

따라서 두 번째 DFS에서 한 번 시작한 탐색은 정확히 하나의 SCC를 수집한다.

### 시간 복잡도와 공간 복잡도

인접 리스트를 사용하면 다음 시간이 필요하다.

| 단계 | 시간 |
|---|---|
| 원래 그래프의 DFS | O(\|V\| + \|E\|) |
| 전치 그래프 구성 | O(\|V\| + \|E\|) |
| 전치 그래프의 DFS | O(\|V\| + \|E\|) |

종료 순서를 DFS 중에 기록하면 별도의 정렬은 필요 없다.

따라서 전체 시간 복잡도는 다음과 같다.

$$
\Theta(|V|+|E|)
$$

전치 그래프를 별도로 저장하면 O(|V| + |E|) 공간이 필요하다.

방문 상태, 종료 순서, 결과와 DFS 스택에는 O(|V|) 공간이 필요하다.

## 서로소 집합

서로소 집합(Disjoint Set)은 공통 원소가 없는 여러 집합을 관리하는 자료구조이다.

서로소 집합 자료구조는 Union-Find라고도 한다.

### 서로소 집합의 의미

두 집합의 교집합이 공집합이면 두 집합은 서로소이다.

$$
A\cap B=\varnothing
$$

예를 들어 다음 집합들은 서로소이다.

```
{0, 1, 2}
{3, 4}
{5}
```

서로소 집합 자료구조는 각 원소가 어느 집합에 속하는지 관리하고, 두 집합을 하나로 합칠 수 있다.

각 집합은 대표자(Representative)로 구분한다.

대표자가 반드시 가장 작은 원소일 필요는 없다.

중요한 것은 같은 집합의 원소들이 같은 대표자로 식별된다는 점이다.

집합을 합치면 대표자는 이전과 달라질 수 있다.

### 기본 연산

| 연산 | 의미 |
|---|---|
| MAKE-SET(x) | 원소 x만 포함하는 새 집합을 만든다. |
| FIND-SET(x) | x가 속한 집합의 대표자를 반환한다. |
| UNION(x, y) | x와 y가 속한 두 집합을 합친다. |

처음에는 각 원소를 자기 자신만 포함하는 집합으로 만들 수 있다.

```
{0} {1} {2} {3}
```

UNION(0, 1)을 수행하면 두 집합을 합친다.

```
{0, 1} {2} {3}
```

UNION(1, 2)를 수행하면 1이 속한 집합과 2가 속한 집합을 합친다.

```
{0, 1, 2} {3}
```

두 원소가 같은 집합에 속하는지는 대표자를 비교하여 확인한다.

```
FIND-SET(x) == FIND-SET(y)
```

이미 같은 집합에 속한 두 원소에 UNION을 수행하면 집합 구성은 변하지 않는다.

n개의 원소가 각각 별도 집합에서 시작한다면, 서로 다른 두 집합을 실제로 합치는 성공적인 UNION은 최대 n-1번이다.

이미 같은 집합에 속한 원소에 대한 UNION 호출은 여러 번 수행할 수 있다.

### 연결 관계 예제

정점 0부터 9까지 각각을 별도 집합으로 만든다고 하자.

다음 간선을 순서대로 처리하면서 양 끝 정점의 집합을 합친다.

```
(0, 1)
(0, 2)
(1, 3)
(4, 8)
(5, 6)
(5, 7)
```

결과 집합은 다음과 같다.

```
{0, 1, 2, 3}
{4, 8}
{5, 6, 7}
{9}
```

다음 연결 관계를 확인해 보자.

| 확인할 정점 | 같은 집합인가? | 결과 |
|---|---|---|
| 0과 3 | 예 | 연결됨 |
| 1과 5 | 아니요 | 연결되지 않음 |
| 7과 8 | 아니요 | 연결되지 않음 |

이후 간선 (4, 5)를 추가하고 UNION(4, 5)를 수행하면 다음 두 집합이 합쳐진다.

```
{4, 8} + {5, 6, 7}
             ↓
{4, 5, 6, 7, 8}
```

그러면 7과 8도 같은 집합이 된다.

이 방식은 **무방향 간선이 추가되는 상황의 연결 요소**를 관리하는 데 사용할 수 있다.

방향 간선의 방향을 무시하고 합치면 약한 연결 관계를 관리하는 것이며, 일반적인 방향 그래프의 도달 가능성이나 SCC를 구하는 것은 아니다.

또한 기본적인 서로소 집합 연산에는 이미 합친 집합을 다시 분리하거나 간선을 삭제하는 기능이 없다.

## 서로소 집합의 구현

서로소 집합은 대표자를 저장하는 방식에 따라 여러 방법으로 구현할 수 있다.

### Quick Find

Quick Find에서는 각 원소가 속한 집합의 식별자를 배열에 직접 저장한다.

예를 들어 다음 배열을 생각해 보자.

| 원소 | 0 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|---:|
| id | 0 | 0 | 2 | 2 | 4 |

같은 id를 가진 원소는 같은 집합에 속한다.

```
{0, 1}
{2, 3}
{4}
```

#### FIND

x의 집합 식별자를 배열에서 바로 읽는다.

```
FIND(x)
    return id[x]
```

시간 복잡도는 O(1)이다.

#### UNION

두 집합을 합치려면 한 집합에 속한 모든 원소의 id를 다른 집합의 id로 바꾼다.

```
UNION(x, y)
    oldId = id[x]
    newId = id[y]

    if oldId == newId
        return

    for i = 0 to n - 1
        if id[i] == oldId
            id[i] = newId
```

최악의 경우 배열 전체를 확인하므로 UNION은 O(n)이다.

두 원소가 같은 집합인지 확인하는 연산은 id 두 개를 비교하므로 O(1)이다.

### Quick Union

Quick Union에서는 각 집합을 부모 포인터로 연결된 트리로 표현한다.

각 원소는 parent 배열에 자신의 부모를 저장한다.

루트는 자기 자신을 부모로 가진다.

```
parent[root] = root
```

같은 트리에 속한 원소들은 같은 집합이다.

#### FIND

현재 원소에서 부모를 따라 루트까지 이동한다.

```
FIND(x)
    while parent[x] != x
        x = parent[x]

    return x
```

루트가 해당 집합의 대표자이다.

#### UNION

두 원소의 루트를 찾은 뒤 한 루트를 다른 루트의 자식으로 만든다.

```
UNION(x, y)
    rootX = FIND(x)
    rootY = FIND(y)

    if rootX == rootY
        return

    parent[rootX] = rootY
```

반드시 루트끼리 연결해야 기존 집합의 모든 원소가 함께 합쳐진다.

최적화하지 않으면 트리가 한쪽으로 길게 늘어설 수 있다.

```
0 → 1 → 2 → 3 → 4
```

이 경우 루트를 찾는 데 O(n) 시간이 걸릴 수 있다.

UNION과 연결 여부 확인도 FIND를 사용하므로 최악의 경우 O(n)이다.

### 랭크를 이용한 합치기

랭크를 이용한 합치기(Union by Rank)는 트리가 지나치게 깊어지는 것을 줄이기 위한 방법이다.

각 루트에 랭크를 저장하고, 랭크가 작은 트리의 루트를 랭크가 큰 트리의 루트 아래에 붙인다.

두 루트의 랭크가 같을 때는 한쪽을 다른 쪽 아래에 붙이고, 새 루트의 랭크를 1 증가시킨다.

```
UNION-BY-RANK(x, y)
    rootX = FIND(x)
    rootY = FIND(y)

    if rootX == rootY
        return

    if rank[rootX] < rank[rootY]
        parent[rootX] = rootY
    else if rank[rootX] > rank[rootY]
        parent[rootY] = rootX
    else
        parent[rootY] = rootX
        rank[rootX] = rank[rootX] + 1
```

처음 각 원소가 하나의 트리일 때 랭크는 0으로 초기화한다.

경로 압축을 사용하지 않는 랭크 기반 구현에서는 같은 랭크의 트리를 합칠 때만 높이가 증가한다.

따라서 트리 높이를 O(log n)으로 제한할 수 있다.

#### 랭크와 크기의 차이

랭크 기반 합치기와 크기 기반 합치기는 서로 비슷하지만 기준이 다르다.

| 방법 | 합치는 기준 |
|---|---|
| Union by Rank | 루트의 랭크가 작은 트리를 큰 쪽에 붙인다. |
| Union by Size | 원소 수가 적은 트리를 많은 쪽에 붙인다. |

경로 압축을 함께 사용하면 랭크는 실제 트리 높이와 달라질 수 있다.

이때 랭크는 높이를 관리하기 위한 상한으로 생각할 수 있다.

랭크가 더 작은 트리가 반드시 원소 수도 더 적다는 뜻은 아니다.

### 경로 압축

경로 압축(Path Compression)은 FIND를 수행하면서 지나간 노드들이 루트를 직접 가리키도록 변경하는 최적화이다.

예를 들어 다음 부모 관계가 있다고 하자.

```
0 → 1 → 2 → 3
```

3이 루트라고 하자.

0에서 FIND를 수행하여 루트 3을 찾은 뒤, 경로의 노드들이 3을 직접 가리키도록 바꿀 수 있다.

```
0 ─→ 3
1 ─→ 3
2 ─→ 3
```

경로 압축을 포함한 재귀 FIND는 다음과 같다.

```
FIND(x)
    if parent[x] != x
        parent[x] = FIND(parent[x])

    return parent[x]
```

재귀 호출이 루트에 도달한 뒤 돌아오면서 각 노드의 부모를 루트로 갱신한다.

경로 압축은 집합에 속한 원소를 바꾸지 않는다.

같은 대표자에 도달하는 경로를 짧게 만들 뿐이다.

### 최적화된 서로소 집합

랭크를 이용한 합치기와 경로 압축을 함께 사용할 수 있다.

```
MAKE-SET(x)
    parent[x] = x
    rank[x] = 0
```

```
FIND(x)
    if parent[x] != x
        parent[x] = FIND(parent[x])

    return parent[x]
```

```
UNION(x, y)
    rootX = FIND(x)
    rootY = FIND(y)

    if rootX == rootY
        return

    if rank[rootX] < rank[rootY]
        parent[rootX] = rootY
    else if rank[rootX] > rank[rootY]
        parent[rootY] = rootX
    else
        parent[rootY] = rootX
        rank[rootX] = rank[rootX] + 1
```

```
CONNECTED(x, y)
    return FIND(x) == FIND(y)
```

n개 원소를 초기화하고 이후 연산을 수행할 때, 랭크와 경로 압축을 함께 사용하면 연산을 매우 빠르게 처리할 수 있다.

n번의 MAKE-SET을 포함한 총 m번의 연산에 대한 대표적인 상한은 다음과 같다.

$$
O(m\alpha(n))
$$

여기서 m ≥ n이고, α(n)은 역 아커만 함수(Inverse Ackermann Function)이다.

α(n)은 n이 매우 커져도 증가가 극히 느리다.

이 복잡도는 여러 연산을 합쳐 분석한 분할 상환(Amortized) 상한이다.

따라서 모든 개별 FIND가 반드시 O(α(n)) 시간에 끝난다는 뜻으로 해석해서는 안 된다.

### 구현 방법의 복잡도 비교

n개 원소를 초기화하는 상황을 기준으로 비교한다.

| 구현 | 초기화 | FIND | UNION | 같은 집합 확인 |
|---|---:|---:|---:|---:|
| Quick Find | O(n) | O(1) | O(n) | O(1) |
| Quick Union | O(n) | O(n) | O(n) | O(n) |
| 랭크 기반 | O(n) | O(log n) | O(log n) | O(log n) |

위 표의 FIND, UNION, 확인 비용은 각 연산의 최악 시간에 대한 상한이다.

랭크 기반 합치기와 경로 압축을 함께 쓰는 경우에는 전체 연산열에 대해 O(mα(n))이라는 더 강한 분할 상환 상한을 사용할 수 있다.

모든 구현에서 원소별 배열을 저장하므로 기본 공간 복잡도는 O(n)이다.

## 정리

DFS는 정점을 탐색하는 것뿐 아니라 방향 그래프의 구조를 분석하는 데 사용할 수 있다.

| 문제 | 핵심 아이디어 | 인접 리스트 기준 시간 |
|---|---|---|
| 위상 정렬 | DAG에서 DFS 종료 시간의 내림차순으로 정점을 나열 | Θ(\|V\| + \|E\|) |
| 강한 연결 요소 | 원래 그래프의 종료 순서와 전치 그래프의 DFS를 사용 | Θ(\|V\| + \|E\|) |

위상 정렬은 모든 간선 u → v에 대해 u가 v보다 앞에 나오도록 정점을 나열한다.

방향 사이클이 있으면 위상 정렬은 존재하지 않는다.

강한 연결 요소는 서로 양방향으로 도달할 수 있는 정점들의 최대 집합이다.

각 SCC를 하나의 정점으로 줄여 만든 요소 그래프는 DAG이다.

서로소 집합은 서로 겹치지 않는 집합들을 관리하며, 대표자를 통해 두 원소가 같은 집합에 속하는지 확인한다.

랭크를 이용한 합치기와 경로 압축을 함께 사용하면 여러 FIND와 UNION 연산을 효율적으로 처리할 수 있다.
