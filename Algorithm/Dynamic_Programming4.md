## 동적 계획법의 설계 과정

동적 계획법으로 최적화 문제를 해결할 때는 다음 네 단계를 따른다.

1. 최적해의 구조를 분석한다.

2. 최적값을 재귀적인 점화식으로 정의한다.

3. 부분 문제의 최적값을 계산한다.

4. 저장한 정보를 이용하여 실제 최적해를 복원한다.

이번에는 최장 공통 부분 수열과 최적 이진 탐색 트리에 이 과정을 적용한다.

두 문제 모두 최적 부분 구조와 중복되는 부분 문제를 이용하지만, 상태와 선택의 의미는 서로 다르다.

## 최장 공통 부분 수열

최장 공통 부분 수열(Longest Common Subsequence, LCS)은 두 수열에 공통으로 나타나는 부분 수열 중 길이가 가장 긴 것이다.

### 부분 수열과 부분 문자열

부분 수열(Subsequence)은 원래 수열에서 일부 원소를 제거하되, 남은 원소의 상대적인 순서를 유지하여 얻는 수열이다.

원소가 연속해서 등장할 필요는 없다.

예를 들어 다음 수열을 생각해 보자.

```
X = A B C B D A B
```

다음은 X의 부분 수열이다.

```
A C D B
B C B A
B D A B
```

반면 D C는 부분 수열이 아니다. X에서는 D가 C보다 뒤에 있기 때문이다.

문자열에서 연속된 구간을 뜻하는 부분 문자열(Substring)과도 구분해야 한다.

| 구분 | 순서 유지 | 연속성 필요 |
|---|---|---|
| 부분 수열 | 필요 | 불필요 |
| 부분 문자열 | 필요 | 필요 |

LCS는 문자뿐 아니라 수나 다른 원소로 이루어진 수열에도 정의할 수 있다.

### 문제 정의

- 입력: 길이가 각각 m과 n인 두 수열 X와 Y
- 출력: 두 수열의 LCS 길이와 실제 LCS 하나
- 조건:
  - 원소의 상대적인 순서를 유지한다.
  - 원소가 연속할 필요는 없다.
  - 같은 값도 서로 다른 위치에 여러 번 등장할 수 있다.

예제를 통해 살펴보자.

```
X = A B C B D A B
Y = B D C A B A
```

두 수열의 LCS 길이는 4이다.

다음은 모두 길이가 4인 LCS이다.

```
B C B A
B D A B
B C A B
```

다음 수열도 두 입력의 공통 부분 수열이지만 길이가 3이므로 LCS는 아니다.

```
B C A
```

공통 부분 수열과 최장 공통 부분 수열은 구분해야 한다.

### 완전 탐색의 한계

X의 각 위치에서 해당 원소를 선택하거나 선택하지 않을 수 있다.

따라서 위치 선택을 기준으로 하면 X의 부분 수열 후보는 2ᵐ개이다.

중복된 원소가 있으면 서로 다른 위치 선택이 같은 값의 부분 수열을 만들 수 있지만, 위치 선택 자체는 2ᵐ가지이다.

각 후보가 Y의 부분 수열인지 확인하려면 Y를 왼쪽부터 순서대로 탐색한다.

```
후보: B C A
Y:    B D C A B A
      ↑   ↑ ↑
```

한 후보를 검사할 때 Y를 반복해서 처음부터 탐색할 필요는 없다. 이전에 찾은 위치 다음부터 계속 탐색하면 된다.

후보 검사 비용을 O(n)으로 보면 전체 검사 비용의 상한은 다음과 같다.

$$
O(n2^m)
$$

강의에서는 이를 지수 시간의 완전 탐색으로 설명한다.

실제 구현의 전체 비용에는 후보를 생성하고 복사하는 비용도 포함해야 한다.

두 수열 중 짧은 쪽의 부분 수열을 열거하면 후보 수를 줄일 수 있지만, 여전히 지수적으로 증가한다.

## LCS의 최적 부분 구조와 점화식

### 접두사와 상태 정의

X의 처음 i개 원소로 이루어진 접두사를 Xᵢ라고 하자.

$$
X_i=\langle x_1,x_2,\ldots,x_i\rangle
$$

Y의 처음 j개 원소로 이루어진 접두사도 같은 방식으로 정의한다.

$$
Y_j=\langle y_1,y_2,\ldots,y_j\rangle
$$

X₀와 Y₀는 빈 수열이다.

예를 들어 X = ABCBDAB이면 다음과 같다.

```
X0 = 빈 수열
X1 = A
X4 = A B C B
X7 = A B C B D A B
```

상태 c[i, j]를 다음과 같이 정의한다.

$$
c[i,j]
=
X_i\text{와 }Y_j\text{의 LCS 길이}
$$

부분 문제는 두 접두사의 길이 i와 j로 식별된다.

### 마지막 원소가 같은 경우

두 접두사의 마지막 원소가 같다고 하자.

$$
x_i=y_j
$$

이 공통 원소를 마지막에 사용하는 LCS를 구성할 수 있다.

그 앞부분은 Xᵢ₋₁과 Yⱼ₋₁의 LCS로 선택하면 된다.

$$
c[i,j]=c[i-1,j-1]+1
$$

예를 들어 다음 두 수열을 생각해 보자.

```
X = A B C
Y = B A C
```

마지막 원소 C가 같으므로 다음 작은 문제를 해결하고 C를 붙인다.

```
X의 앞부분: A B
Y의 앞부분: B A
```

앞부분의 LCS 길이는 1이고, 전체 LCS 길이는 2이다.

앞부분이 최적이 아니라면 더 긴 공통 부분 수열로 교체한 뒤 같은 마지막 원소를 붙여 전체 길이를 늘릴 수 있다.

따라서 앞부분도 최적이어야 한다.

### 마지막 원소가 다른 경우

마지막 원소가 다르면 두 원소를 모두 마지막 원소로 대응시킬 수 없다.

$$
x_i\ne y_j
$$

따라서 다음 두 경우를 비교한다.

1. X의 마지막 원소 xᵢ를 제외한다.

2. Y의 마지막 원소 yⱼ를 제외한다.

$$
c[i,j]=\max(c[i-1,j],c[i,j-1])
$$

여기서 원소를 제외한다는 것은 해당 후보의 대응에서 사용하지 않는다는 뜻이다. 입력 수열 자체를 수정할 필요는 없다.

각 후보는 작은 접두사 문제의 LCS를 사용한다.

### LCS 길이의 점화식

한쪽 수열이 비어 있으면 공통 부분 수열의 길이는 0이다.

이를 포함하면 다음 점화식을 얻는다.

$$
c[i,j]=
\begin{cases}
0
& \text{if } i=0 \text{ or } j=0, \\[4pt]
c[i-1,j-1]+1
& \text{if } i,j>0 \text{ and } x_i=y_j, \\[4pt]
\max(c[i-1,j],c[i,j-1])
& \text{if } i,j>0 \text{ and } x_i\ne y_j.
\end{cases}
$$

최종적으로 구하려는 길이는 c[m, n]이다.

단순 재귀로 계산하면 서로 다른 경로에서 같은 c[i, j]가 반복해서 필요하다.

따라서 결과를 저장하고 재사용한다.

## LCS의 상향식 계산

### 계산 알고리즘

c[i, j]를 계산하려면 위쪽, 왼쪽, 왼쪽 위의 상태가 먼저 계산되어 있어야 한다.

$$
c[i-1,j],\qquad c[i,j-1],\qquad c[i-1,j-1]
$$

첫 행과 첫 열을 0으로 초기화한 뒤, 왼쪽 위에서 오른쪽 아래로 테이블을 채울 수 있다.

최적해 복원을 위해 선택한 방향을 b에 함께 저장한다.

| 방향 | 의미 |
|---|---|
| ↖ | 두 원소가 같으므로 둘을 대응시킨다. |
| ↑ | X의 마지막 원소를 제외한다. |
| ← | Y의 마지막 원소를 제외한다. |

```
LCS-LENGTH(X, Y)
    m = X.length
    n = Y.length

    c = new table[0..m, 0..n]
    b = new table[1..m, 1..n]

    for i = 0 to m
        c[i, 0] = 0

    for j = 0 to n
        c[0, j] = 0

    for i = 1 to m
        for j = 1 to n
            if X[i] == Y[j]
                c[i, j] = c[i - 1, j - 1] + 1
                b[i, j] = "↖"
            else if c[i - 1, j] >= c[i, j - 1]
                c[i, j] = c[i - 1, j]
                b[i, j] = "↑"
            else
                c[i, j] = c[i, j - 1]
                b[i, j] = "←"

    return c, b
```

이 의사코드에서 수열의 인덱스는 1부터 시작한다.

C++ 문자열처럼 인덱스가 0부터 시작하는 입력을 사용하면 X[i-1]과 Y[j-1]을 비교해야 한다.

위쪽과 왼쪽의 길이가 같으면 위쪽을 선택한다. 이 동점 처리 규칙은 복원되는 LCS에 영향을 줄 수 있지만 최장 길이는 바꾸지 않는다.

### 길이 테이블

```text
X = A B C B D A B
Y = B D C A B A
```

완성된 c 테이블은 다음과 같다.

| i ＼ j | 0: 빈 수열 | 1: B | 2: D | 3: C | 4: A | 5: B | 6: A |
|---|---:|---:|---:|---:|---:|---:|---:|
| 0: 빈 수열 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 1: A | 0 | 0 | 0 | 0 | 1 | 1 | 1 |
| 2: B | 0 | 1 | 1 | 1 | 1 | 2 | 2 |
| 3: C | 0 | 1 | 1 | 2 | 2 | 2 | 2 |
| 4: B | 0 | 1 | 1 | 2 | 2 | 3 | 3 |
| 5: D | 0 | 1 | 2 | 2 | 2 | 3 | 3 |
| 6: A | 0 | 1 | 2 | 2 | 3 | 3 | 4 |
| 7: B | 0 | 1 | 2 | 2 | 3 | 4 | 4 |

예를 들어 X₃ = ABC와 Y₃ = BDC의 마지막 원소는 C로 같다.

따라서 다음과 같다.

$$
c[3,3]=c[2,2]+1=2
$$

전체 입력의 LCS 길이는 다음과 같다.

$$
c[7,6]=4
$$

### 방향 테이블

위쪽을 우선하는 동점 처리 규칙을 적용한 b 테이블은 다음과 같다.

| i ＼ j | 1: B | 2: D | 3: C | 4: A | 5: B | 6: A |
|---|---|---|---|---|---|---|
| 1: A | ↑ | ↑ | ↑ | ↖ | ← | ↖ |
| 2: B | ↖ | ← | ← | ↑ | ↖ | ← |
| 3: C | ↑ | ↑ | ↖ | ← | ↑ | ↑ |
| 4: B | ↖ | ↑ | ↑ | ↑ | ↖ | ← |
| 5: D | ↑ | ↖ | ↑ | ↑ | ↑ | ↑ |
| 6: A | ↑ | ↑ | ↑ | ↖ | ↑ | ↖ |
| 7: B | ↖ | ↑ | ↑ | ↑ | ↖ | ↑ |

### 시간 복잡도와 공간 복잡도

빈 접두사를 포함한 상태 수는 다음과 같다.

$$
(m+1)(n+1)
$$

각 상태는 상수 개의 이전 상태를 참조하고, 비교나 덧셈을 상수 시간에 수행한다.

m, n ≥ 1에서 시간 복잡도는 다음과 같다.

$$
T(m,n)=\Theta(mn)
$$

첫 행과 첫 열의 초기화까지 포함하면 Θ(mn+m+n)이다.

빈 입력이 있는 경우에는 그 길이에 대한 기저 처리를 수행한다.

길이 테이블과 방향 테이블의 공간은 각각 다음과 같다.

$$
\Theta((m+1)(n+1))
$$

m, n ≥ 1이면 보통 Θ(mn)으로 표현한다.

## LCS의 최적해 복원

### 방향 테이블을 이용한 복원

c[m, n]은 최장 길이만 알려 준다.

실제 LCS를 구하려면 b[m, n]부터 저장된 방향을 따라간다.

```
PRINT-LCS(b, X, i, j)
    if i == 0 or j == 0
        return

    if b[i, j] == "↖"
        PRINT-LCS(b, X, i - 1, j - 1)
        print X[i]
    else if b[i, j] == "↑"
        PRINT-LCS(b, X, i - 1, j)
    else
        PRINT-LCS(b, X, i, j - 1)
```

전체 입력에 대해서는 다음과 같이 호출한다.

```
PRINT-LCS(b, X, m, n)
```

대각선 방향일 때 재귀 호출이 끝난 다음 원소를 출력하므로, 원래 수열의 순서대로 결과가 출력된다.

반복문으로 뒤에서부터 복원한다면 원소를 모은 뒤 순서를 뒤집어야 한다.

### 복원 예제

위 방향 테이블에서 복원 경로는 다음과 같다.

| 현재 상태 | 방향 | 처리 |
|---|---|---|
| [7, 6] | ↑ | X의 마지막 B 제외 |
| [6, 6] | ↖ | A 선택 |
| [5, 5] | ↑ | D 제외 |
| [4, 5] | ↖ | B 선택 |
| [3, 4] | ← | Y의 A 제외 |
| [3, 3] | ↖ | C 선택 |
| [2, 2] | ← | Y의 D 제외 |
| [2, 1] | ↖ | B 선택 |
| [1, 0] | 종료 | 빈 접두사 도달 |

뒤에서부터 선택한 원소는 다음과 같다.

```
A B C B
```

이를 원래 순서로 정리하면 다음 LCS를 얻는다.

```
B C B A
```

각 이동에서 i 또는 j가 감소하므로 복원 시간은 O(m+n)이다.

재귀 방식의 스택 공간도 최악의 경우 O(m+n)이다.

하나의 복원 경로는 LCS 하나를 구한다. 가능한 모든 LCS를 구하려면 동점 분기와 중복 결과를 추가로 처리해야 하며, 결과 개수 자체가 매우 많을 수 있다.

### 길이 테이블만 이용한 복원

방향 테이블 b가 없어도 원래 입력과 c 테이블을 이용하여 복원할 수 있다.

- X[i] = Y[j]이면 해당 원소를 선택하고 대각선으로 이동한다.
- 다르면 c[i-1, j]와 c[i, j-1]을 비교하여 더 큰 쪽으로 이동한다.
- 같으면 정해 둔 동점 처리 규칙을 적용한다.

따라서 b는 복원을 편리하게 만드는 정보이며, 반드시 저장해야 하는 것은 아니다.

다만 전체 c 테이블을 유지하는 경우 공간 복잡도는 여전히 Θ(mn)이다.

### 길이만 필요한 경우의 공간 최적화

현재 행을 계산할 때 필요한 것은 이전 행과 현재 행의 왼쪽 값이다.

따라서 길이만 필요하면 모든 행을 보관하지 않아도 된다.

한 행만 사용하는 의사코드는 다음과 같다.

```
LCS-LENGTH-SPACE-OPTIMIZED(X, Y)
    if X.length < Y.length
        swap X and Y

    m = X.length
    n = Y.length

    dp = new array[0..n] filled with 0

    for i = 1 to m
        diagonal = 0

        for j = 1 to n
            above = dp[j]

            if X[i] == Y[j]
                dp[j] = diagonal + 1
            else
                dp[j] = max(dp[j], dp[j - 1])

            diagonal = above

    return dp[n]
```

각 반복에서 값의 의미는 다음과 같다.

| 값 | 의미 |
|---|---|
| 갱신 전 dp[j] | 이전 행의 c[i-1, j] |
| 갱신된 dp[j-1] | 현재 행의 c[i, j-1] |
| diagonal | 이전 행의 c[i-1, j-1] |

시간 복잡도는 O(mn)으로 유지된다.

추가 배열 공간은 O(min(m,n)+1)이다.

이 구현은 최장 길이만 반환한다. 모든 과거 상태를 덮어쓰므로 앞서 설명한 단순한 역추적으로 실제 LCS를 복원할 수는 없다.

## 최적 이진 탐색 트리

최적 이진 탐색 트리(Optimal Binary Search Tree, Optimal BST)는 각 탐색의 발생 확률을 고려하여 기대 탐색 비용이 최소가 되도록 구성한 이진 탐색 트리이다.

### 문제 정의

이진 탐색 트리(Binary Search Tree, BST)는 각 노드에 대하여 다음 순서를 만족한다.

- 왼쪽 서브트리의 모든 키는 해당 노드의 키보다 작다.
- 오른쪽 서브트리의 모든 키는 해당 노드의 키보다 크다.

서로 다른 키들이 다음과 같이 정렬되어 있다고 하자.

$$
k_1<k_2<\cdots<k_n
$$

- 입력: 정렬된 키들과 성공·실패 탐색 확률
- 출력: 기대 탐색 비용이 최소인 BST와 그 비용
- 조건:
  - BST의 키 순서를 유지한다.
  - 탐색 확률은 고정되어 있다고 가정한다.
  - 성공 탐색뿐 아니라 실패 탐색도 고려한다.

균형 잡힌 트리는 최악의 탐색 깊이를 줄이는 데 유리하다.

하지만 키별 탐색 확률이 다르면 높이가 최소인 트리가 반드시 기대 비용까지 최소화하는 것은 아니다.

자주 탐색되는 키를 더 얕은 곳에 두는 것이 유리할 수 있다. 다만 가장 확률이 높은 키를 무조건 루트로 고르는 단순한 방법이 항상 최적인 것은 아니다.

### 기댓값과 탐색 확률

확률 변수 Z가 값 z₁, ..., zₜ를 각각 확률 a₁, ..., aₜ로 가진다면 기댓값은 다음과 같다.

$$
E[Z]=\sum_{\ell=1}^{t}z_\ell a_\ell
$$

예를 들어 공정한 주사위의 눈에 대한 기댓값은 다음과 같다.

$$
E[Z]
=
\frac{1+2+3+4+5+6}{6}
=
3.5
$$

기댓값은 가능한 결과들을 확률로 가중한 평균이다. 실제 결과 중 하나와 반드시 같을 필요는 없다.

BST에서는 각 탐색 비용에 해당 탐색이 발생할 확률을 곱하여 합한다.

실제 키 kᵢ를 탐색할 확률을 pᵢ라고 하자.

$$
p_i=P(\text{탐색 대상이 }k_i)
$$

### 실패 탐색과 더미 키

찾으려는 값이 트리에 없는 경우도 고려해야 한다.

정렬된 키가 n개이면 실패하는 탐색 값은 다음 n+1개 구간으로 나뉜다.

| 더미 키 | 나타내는 탐색 값 |
|---|---|
| d₀ | k₁보다 작은 값 |
| dᵢ, 1 ≤ i < n | kᵢ보다 크고 kᵢ₊₁보다 작은 값 |
| dₙ | kₙ보다 큰 값 |

더미 키 dᵢ는 실제 저장된 키가 아니라, 해당 구간에서 탐색이 실패했음을 표현하는 외부 노드이다.

해당 실패 구간에 속하는 값을 탐색할 확률을 qᵢ라고 하자.

모든 탐색은 성공하거나 실패하므로 다음 관계를 만족한다.

$$
\sum_{i=1}^{n}p_i+\sum_{i=0}^{n}q_i=1
$$

### 기대 탐색 비용

루트의 깊이는 0으로 정의한다.

성공 탐색으로 깊이 d의 실제 키를 찾으면 d+1개의 실제 키 노드를 방문한다.

여기서는 실패 탐색에 대해서도 마지막 더미 노드를 방문하는 비용까지 포함하여, 다음 식을 사용한다.

$$
E[T]
=
\sum_{i=1}^{n}
\left(\operatorname{depth}_T(k_i)+1\right)p_i
+
\sum_{i=0}^{n}
\left(\operatorname{depth}_T(d_i)+1\right)q_i
$$

확률의 전체 합이 1이므로 다음과 같이 표현할 수도 있다.

$$
E[T]
=
1+
\sum_{i=1}^{n}\operatorname{depth}_T(k_i)p_i
+
\sum_{i=0}^{n}\operatorname{depth}_T(d_i)q_i
$$

더미 노드는 개념적인 실패 위치이므로, 실제 코드에서 더미 객체를 생성해야 한다는 뜻은 아니다.

실제 키와 비교한 횟수만 세는 모델에서는 실패 탐색의 비용이 더미 노드의 깊이가 된다.

두 모델의 차이는 다음 상수이다.

$$
E_{\text{현재 모델}}[T]
-
E_{\text{실제 키 비교}}[T]
=
\sum_{i=0}^{n}q_i
$$

확률이 고정되어 있다면 모든 트리에 같은 상수가 더해지므로 최적 트리의 선택은 바뀌지 않는다.

이후 점화식과 예제에서는 더미 노드 비용을 포함하는 모델을 사용한다.

### 두 트리의 비용 비교

| i | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|---:|
| pᵢ | — | 0.15 | 0.10 | 0.05 | 0.10 | 0.20 |
| qᵢ | 0.05 | 0.10 | 0.05 | 0.05 | 0.05 | 0.10 |

성공 확률의 합은 0.60이고, 실패 확률의 합은 0.40이다.

첫 번째 트리의 실제 키 구조는 다음과 같다.

```text
        k2
       /  \
     k1    k4
          /  \
        k3    k5
```

두 번째 트리는 다음과 같다.

```text
        k2
       /  \
     k1    k5
          /
        k4
       /
     k3
```

비어 있는 자식 위치에 해당하는 더미 노드까지 고려하면 비용 기여도는 다음과 같다.

각 기여도는 (깊이+1)×확률이다.

| 노드 | 확률 | 첫 번째 깊이 | 첫 번째 기여도 | 두 번째 깊이 | 두 번째 기여도 |
|---|---:|---:|---:|---:|---:|
| k₁ | 0.15 | 1 | 0.30 | 1 | 0.30 |
| k₂ | 0.10 | 0 | 0.10 | 0 | 0.10 |
| k₃ | 0.05 | 2 | 0.15 | 3 | 0.20 |
| k₄ | 0.10 | 1 | 0.20 | 2 | 0.30 |
| k₅ | 0.20 | 2 | 0.60 | 1 | 0.40 |
| d₀ | 0.05 | 2 | 0.15 | 2 | 0.15 |
| d₁ | 0.10 | 2 | 0.30 | 2 | 0.30 |
| d₂ | 0.05 | 3 | 0.20 | 4 | 0.25 |
| d₃ | 0.05 | 3 | 0.20 | 4 | 0.25 |
| d₄ | 0.05 | 3 | 0.20 | 3 | 0.20 |
| d₅ | 0.10 | 3 | 0.40 | 2 | 0.30 |
| 합계 | 1.00 | — | 2.80 | — | 2.75 |

두 번째 트리는 최대 깊이가 더 크지만 기대 탐색 비용은 더 작다.

따라서 트리 높이만으로 기대 비용의 최적 여부를 판단할 수 없다.

## 최적 BST의 최적 부분 구조와 점화식

### 루트 선택과 부분 문제

연속된 키 kᵢ, ..., kⱼ로 BST를 만든다고 하자.

그중 어떤 키 kᵣ을 루트로 정하면 BST의 순서 조건에 따라 두 부분 문제가 결정된다.

- 왼쪽 서브트리: kᵢ, ..., kᵣ₋₁
- 오른쪽 서브트리: kᵣ₊₁, ..., kⱼ

$$
i\le r\le j
$$

전체 트리가 최적이라면 두 서브트리도 각각 최적이어야 한다.

한 서브트리를 더 작은 기대 비용의 트리로 바꿀 수 있다고 가정하자.

같은 키 집합으로 만든 서브트리이므로 BST의 순서 조건을 유지한다.

또한 그 서브트리에 속하는 전체 탐색 확률은 변하지 않는다.

따라서 해당 부분을 교체하면 전체 기대 비용도 감소하여 원래 트리가 최적이라는 가정과 모순된다.

### 상태와 기저 사례

상태 e[i, j]를 다음과 같이 정의한다.

```text
e[i, j]:
실제 키 ki, ..., kj와
더미 키 d(i-1), ..., dj로 이루어진
최적 서브트리의 최소 기대 비용 기여도
```

서브트리의 루트 깊이는 0으로 두고, 원래 입력의 확률을 그대로 사용한다.

서브트리에 도달했다는 조건으로 확률을 다시 정규화한 조건부 기댓값은 아니다.

실제 키가 하나도 없는 구간도 필요하다.

$$
j=i-1
$$

이 경우에는 더미 키 dᵢ₋₁만 존재한다.

강의의 비용 모델에서는 깊이 0인 더미 노드의 비용이 1이므로 다음과 같다.

$$
e[i,i-1]=q_{i-1}
$$

행렬 연쇄 곱셈의 빈 계산 비용과 달리, 이 기저값은 일반적으로 0이 아니다.

### 확률의 합과 깊이 증가

구간 [i, j]에 속하는 탐색 확률의 합을 w[i, j]라고 하자.

$$
w[i,j]
=
\sum_{\ell=i}^{j}p_\ell
+
\sum_{\ell=i-1}^{j}q_\ell
$$

빈 구간에서는 다음과 같다.

$$
w[i,i-1]=q_{i-1}
$$

기존 서브트리를 어떤 노드의 자식으로 붙이면 해당 서브트리의 모든 노드 깊이가 1씩 증가한다.

각 탐색의 비용이 1씩 증가하므로 기대 비용의 증가량은 해당 서브트리의 확률 합이다.

예를 들어 왼쪽 서브트리를 루트 kᵣ 아래에 붙이면 비용은 다음과 같이 변한다.

$$
e[i,r-1]+w[i,r-1]
$$

오른쪽도 같은 방식으로 처리한다.

### 최소 기대 비용의 점화식

루트가 kᵣ일 때 후보 비용은 다음과 같다.

$$
p_r
+
\left(e[i,r-1]+w[i,r-1]\right)
+
\left(e[r+1,j]+w[r+1,j]\right)
$$

첫 항 pᵣ은 깊이 0에 놓인 루트의 성공 탐색 비용이다.

확률 합은 다음 관계를 만족한다.

$$
w[i,j]
=
w[i,r-1]+p_r+w[r+1,j]
$$

따라서 후보 비용을 다음과 같이 정리할 수 있다.

$$
e[i,r-1]+e[r+1,j]+w[i,j]
$$

가능한 모든 루트 r을 비교하면 다음 점화식을 얻는다.

$$
e[i,j]=
\begin{cases}
q_{i-1}
& \text{if } j=i-1, \\[4pt]
\displaystyle
\min_{i\le r\le j}
\left(
e[i,r-1]+e[r+1,j]+w[i,j]
\right)
& \text{if } i\le j.
\end{cases}
$$

전체 입력의 최소 기대 비용은 e[1, n]이다.

선택한 루트 번호는 별도 테이블 root[i, j]에 저장한다.

## 최적 BST의 상향식 계산

### 계산 알고리즘

e[i, j]는 더 짧은 키 구간의 비용을 참조하므로 구간 길이 순서대로 계산한다.

확률 합도 다음 관계로 갱신할 수 있다.

$$
w[i,j]=w[i,j-1]+p_j+q_j
$$

매번 구간의 확률을 처음부터 합산할 필요가 없다.

```
OPTIMAL-BST(p, q, n)
    e = new table[1..n+1, 0..n]
    w = new table[1..n+1, 0..n]
    root = new table[1..n, 1..n]

    for i = 1 to n + 1
        e[i, i - 1] = q[i - 1]
        w[i, i - 1] = q[i - 1]

    for length = 1 to n
        for i = 1 to n - length + 1
            j = i + length - 1

            e[i, j] = ∞
            w[i, j] = w[i, j - 1] + p[j] + q[j]

            for r = i to j
                cost = e[i, r - 1]
                       + e[r + 1, j]
                       + w[i, j]

                if cost < e[i, j]
                    e[i, j] = cost
                    root[i, j] = r

    return e, w, root
```

빈 왼쪽·오른쪽 서브트리에 해당하는 상태도 필요하므로, e와 w의 행 번호에는 n+1, 열 번호에는 0을 포함한다.

루트 후보를 작은 번호부터 확인하고 비용이 더 작을 때만 갱신하므로, 동점에서는 먼저 찾은 루트를 유지한다.

실수 확률을 사용하는 프로그램에서는 부동소수점 오차가 발생할 수 있다. 수학적인 동점과 구현에서의 비교 결과가 반드시 일치하는 것은 아니다.

### 부분 문제 계산 예제

키가 하나인 구간 [1, 1]에서는 다음과 같다.

$$
w[1,1]
=
q_0+p_1+q_1
=
0.05+0.15+0.10
=
0.30
$$

루트 후보는 k₁뿐이므로 다음과 같다.

$$
\begin{aligned}
e[1,1]
&=e[1,0]+e[2,1]+w[1,1]\\
&=0.05+0.10+0.30\\
&=0.45
\end{aligned}
$$

키가 두 개인 구간 [1, 2]의 확률 합은 다음과 같다.

$$
w[1,2]=0.45
$$

루트 후보를 비교한다.

| 루트 후보 | 비용 | 결과 |
|---|---|---:|
| k₁ | e[1,0] + e[2,2] + w[1,2] | 0.05 + 0.40 + 0.45 = 0.90 |
| k₂ | e[1,1] + e[3,2] + w[1,2] | 0.45 + 0.05 + 0.45 = 0.95 |

따라서 다음 값을 저장한다.

$$
e[1,2]=0.90,\qquad root[1,2]=1
$$

### 기대 비용 테이블

완성된 e 테이블은 다음과 같다.

| i ＼ j | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 0.05 | 0.45 | 0.90 | 1.25 | 1.75 | 2.75 |
| 2 | — | 0.10 | 0.40 | 0.70 | 1.20 | 2.00 |
| 3 | — | — | 0.05 | 0.25 | 0.60 | 1.30 |
| 4 | — | — | — | 0.05 | 0.30 | 0.90 |
| 5 | — | — | — | — | 0.05 | 0.50 |
| 6 | — | — | — | — | — | 0.10 |

j = i-1인 위치는 빈 구간의 기저값이다.

전체 입력의 최소 기대 비용은 다음과 같다.

$$
e[1,5]=2.75
$$

### 확률 합 테이블

| 1 | 0.05 | 0.30 | 0.45 | 0.55 | 0.70 | 1.00 |

| 6 | — | — | — | — | — | 0.10 |

$$
w[1,5]=1
$$

### 루트 테이블

동점에서 작은 번호를 유지하는 경우, root 테이블은 다음과 같다.

| i ＼ j | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| 1 | 1 | 1 | 2 | 2 | 2 |
| 2 | — | 2 | 2 | 2 | 4 |
| 3 | — | — | 3 | 4 | 5 |
| 4 | — | — | — | 4 | 5 |
| 5 | — | — | — | — | 5 |

전체 구간 [1, 5]에서 각 루트 후보를 비교하면 다음과 같다.

| 루트 후보 | 후보 비용 |
|---|---:|
| k₁ | 3.05 |
| k₂ | 2.75 |
| k₃ | 2.80 |
| k₄ | 2.75 |
| k₅ | 2.85 |

최상위 루트로 k₂와 k₄를 선택하는 경우가 모두 최적이다.

위 알고리즘은 먼저 찾은 k₂를 저장한다.

### 시간 복잡도와 공간 복잡도

길이가 ℓ인 키 구간은 n-ℓ+1개이고, 각 구간에서 ℓ개의 루트 후보를 비교한다.

전체 후보 수는 다음과 같다.

$$
\sum_{\ell=1}^{n}(n-\ell+1)\ell
=
\frac{n(n+1)(n+2)}6
=
\Theta(n^3)
$$

각 후보의 비용은 상수 시간에 계산할 수 있으므로 시간 복잡도는 다음과 같다.

$$
T(n)=\Theta(n^3)
$$

e, w, root는 각각 Θ(n²) 공간을 사용한다.

$$
S(n)=\Theta(n^2)
$$

기대 비용만 필요하면 root를 생략할 수 있지만, e 테이블의 공간은 여전히 Θ(n²)이다.

이 분석은 강의에서 제시한 기본 알고리즘에 대한 것이다.

## 최적 BST의 복원

root[i, j]에는 구간 [i, j]의 루트 번호가 저장되어 있다.

해당 번호를 기준으로 좌우 구간을 나누어 재귀적으로 복원한다.

```
BUILD-OPTIMAL-BST(root, i, j)
    if i > j
        return Dummy(i - 1)

    r = root[i, j]

    node = new KeyNode(r)

    node.left = BUILD-OPTIMAL-BST(root, i, r - 1)
    node.right = BUILD-OPTIMAL-BST(root, r + 1, j)

    return node
```

전체 트리는 다음 호출로 복원한다.

```
BUILD-OPTIMAL-BST(root, 1, n)
```

Dummy는 설명을 위한 외부 노드이다. 실제 BST 구현에서는 빈 자식 포인터로 표현해도 된다.

예제의 root 테이블을 따라가면 다음과 같이 선택한다.

```
[1, 5] → k2
├─ [1, 1] → k1
└─ [3, 5] → k5
   └─ [3, 4] → k4
      └─ [3, 3] → k3
```

더미 노드까지 포함한 구조는 다음과 같다.

```
k2
├─ 왼쪽: k1
│  ├─ 왼쪽: d0
│  └─ 오른쪽: d1
└─ 오른쪽: k5
   ├─ 왼쪽: k4
   │  ├─ 왼쪽: k3
   │  │  ├─ 왼쪽: d2
   │  │  └─ 오른쪽: d3
   │  └─ 오른쪽: d4
   └─ 오른쪽: d5
```

앞서 비교한 두 번째 트리이며, 기대 비용은 2.75이다.

실제 키와 비교한 횟수만 세는 모델에서는 실패 확률의 합 0.40을 뺀 2.35가 된다.

복원 과정은 n개의 실제 키와 n+1개의 더미 노드를 방문하므로 Θ(n) 시간이 필요하다.

재귀 스택 공간은 트리 높이에 비례하며, 최악의 경우 O(n)이다.

## 정리

LCS와 최적 BST는 모두 최적 부분 구조와 중복되는 부분 문제를 이용한다.

다만 상태의 의미와 선택 방법은 서로 다르다.

| 항목 | LCS | 최적 BST |
|---|---|---|
| 목적 | 공통 부분 수열의 길이 최대화 | 기대 탐색 비용 최소화 |
| 상태 | 두 접두사의 길이 i, j | 정렬된 키 구간 [i, j] |
| 선택 | 같은 원소를 대응시키거나 한쪽 원소 제외 | 루트로 사용할 키 선택 |
| 기저값 | 한쪽 접두사가 비어 있으면 0 | 빈 구간은 qᵢ₋₁ |
| 계산 순서 | 왼쪽 위에서 오른쪽 아래 | 구간 길이가 짧은 순서 |
| 복원 정보 | 방향 b 또는 길이 c | 루트 번호 root |
| 기본 시간 복잡도 | Θ(mn) | Θ(n³) |
| 기본 테이블 공간 | Θ(mn) | Θ(n²) |

최적값만 구하는 것과 실제 최적해를 복원하는 것은 구분해야 한다.

또한 최적해는 하나로 정해지지 않을 수 있다. 동점 처리에 따라 복원 결과가 달라져도 목적값이 같다면 모두 최적해이다.
