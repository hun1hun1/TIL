## 부호화 문제

부호화(Coding)는 문자를 다른 형태의 기호로 표현하는 것이다.

이번에는 각 문자에 0과 1로 이루어진 비트 문자열을 대응시키는 방법을 살펴본다.

예를 들어 문자 a, b, c를 다음과 같이 표현할 수 있다.

| 문자 | 비트 문자열 |
|---|---|
| a | 00 |
| b | 01 |
| c | 10 |

그러면 문자열 `abc`는 다음과 같이 표현된다.

```
a   b   c
00  01  10

부호화 결과: 000110
```

### 코드와 코드워드

문자 집합의 각 문자에 비트 문자열을 대응시키는 규칙을 코드(Code)라고 한다.

각 문자에 대응된 비트 문자열을 코드워드(Codeword)라고 한다.

위 예제에서 다음과 같다.

```
문자 a의 코드워드: 00
문자 b의 코드워드: 01
문자 c의 코드워드: 10
```

원래 문자열을 코드워드의 나열로 바꾸는 과정을 부호화(Encoding)라고 한다.

반대로 비트 문자열에서 원래 문자열을 복원하는 과정을 복호화(Decoding)라고 한다.

### 고정 길이 코드와 가변 길이 코드

문자마다 사용하는 코드워드의 길이에 따라 코드를 구분할 수 있다.

| 구분 | 설명 |
|---|---|
| 고정 길이 코드 | 모든 문자의 코드워드 길이가 같다. |
| 가변 길이 코드 | 문자에 따라 코드워드 길이가 다를 수 있다. |

서로 다른 문자가 6개라면 고정 길이 코드에서는 문자 하나를 표현하기 위해 최소 3비트가 필요하다.

2비트로는 서로 다른 코드워드를 최대 4개만 만들 수 있기 때문이다.

$$
2^2=4<6\le 8=2^3
$$

일반적으로 서로 다른 문자 n개에 대해 필요한 고정 길이 코드의 최소 비트 수는 다음과 같다.

$$
\lceil\log_2 n\rceil
$$

단, n = 1인 경우 빈 코드워드의 허용 여부와 메시지 길이의 전달 방식에 따라 실제 표현 규칙을 별도로 정해야 한다.

가변 길이 코드에서는 자주 등장하는 문자에 짧은 코드워드를 배정하여 전체 비트 수를 줄일 수 있다.

하지만 코드워드의 길이가 다르면 경계를 구분할 방법도 필요하다.

### 부호화 비용

문자 집합을 C라고 하자.

각 문자 c의 등장 횟수를 f(c), 코드워드 길이를 d(c)라고 하면 전체 부호화 비용은 다음과 같다.

$$
B
=
\sum_{c\in C}f(c)d(c)
$$

예를 들어 문자 a가 45,000번 등장하고 코드워드 길이가 1비트라면 a를 표현하는 데 필요한 비트 수는 다음과 같다.

$$
45{,}000\times 1=45{,}000
$$

전체 부호화 비용을 줄이려면 등장 빈도가 높은 문자에 짧은 코드워드를 배정하는 것이 유리하다.

여기서 계산하는 B는 부호화된 문자 데이터의 비트 수이다.

실제 압축 파일에는 코드 정보, 원본 길이, 파일 형식 등의 추가 정보가 필요할 수 있다.

## 접두 코드

### 접두 코드의 의미

접두사(Prefix)는 문자열의 처음부터 연속하여 일부를 취한 것이다.

예를 들어 `1011`의 접두사에는 다음이 있다.

```
1
10
101
1011
```

접두 코드(Prefix Code)는 어떤 코드워드도 다른 코드워드의 접두사가 되지 않는 코드이다.

접두사가 서로 겹치지 않는다는 의미에서 접두사가 없는 코드(Prefix-Free Code)라고도 한다.

예를 들어 다음 코드를 생각해 보자.

| 문자 | 코드워드 |
|---|---|
| a | 0 |
| b | 10 |
| c | 110 |
| d | 111 |

어떤 코드워드도 다른 코드워드의 접두사가 아니므로 접두 코드이다.

반면 다음 코드는 접두 코드가 아니다.

| 문자 | 코드워드 |
|---|---|
| a | 0 |
| b | 01 |

a의 코드워드 `0`이 b의 코드워드 `01`의 접두사이기 때문이다.

### 접두 코드의 복호화

접두 코드에서는 비트를 앞에서부터 읽다가 하나의 코드워드가 완성되는 즉시 해당 문자를 결정할 수 있다.

다음 코드를 다시 생각해 보자.

| 문자 | 코드워드 |
|---|---|
| a | 0 |
| b | 10 |
| c | 110 |
| d | 111 |

비트 문자열 `0101100`을 앞에서부터 읽으면 다음과 같다.

```
0 | 10 | 110 | 0
a | b  | c   | a
```

따라서 복호화 결과는 `abca`이다.

코드워드 하나가 완성되었을 때 그 코드워드를 접두사로 하는 더 긴 코드워드는 존재하지 않는다.

따라서 코드워드 사이에 별도의 구분자를 넣지 않고도 순서대로 복호화할 수 있다.

접두 코드가 아닌 모든 코드가 반드시 복호화 불가능한 것은 아니다.

다만 접두 코드는 코드워드를 읽는 즉시 경계를 결정할 수 있다는 장점이 있다.

### 이진 트리 표현

이진 접두 코드는 이진 트리로 나타낼 수 있다.

- 루트에서 시작한다.
- 왼쪽 간선은 0으로 표시한다.
- 오른쪽 간선은 1로 표시한다.
- 각 문자는 리프 노드에 저장한다.
- 루트에서 문자 리프까지의 경로가 코드워드가 된다.

앞의 접두 코드는 다음 트리로 나타낼 수 있다.

```
             루트
            /    \
          0/      \1
          a        ●
                  / \
                0/   \1
                 b    ●
                     / \
                   0/   \1
                    c    d
```

경로를 따라가면 다음 코드워드를 얻는다.

```
a: 0
b: 10
c: 110
d: 111
```

문자는 리프에만 저장하므로 한 문자의 코드워드가 다른 문자의 코드워드 앞부분이 될 수 없다.

반대로 어떤 문자 노드가 다른 문자 노드의 조상이라면, 그 문자의 코드워드가 다른 코드워드의 접두사가 된다.

트리에서 문자 c의 깊이를 d(c)라고 하면 코드워드의 길이도 d(c)이다.

따라서 트리 T의 부호화 비용은 다음과 같다.

$$
B(T)
=
\sum_{c\in C}f(c)d_T(c)
$$

여기서 깊이는 루트에서 해당 노드까지의 간선 수이다.

## 허프만 코드

허프만 코드(Huffman Code)는 문자들의 등장 빈도를 이용하여 구성하는 최적 이진 접두 코드이다.

여기서 최적이라는 것은 주어진 문자별 등장 빈도에 대하여 전체 부호화 비용 B(T)가 최소라는 뜻이다.

허프만 알고리즘은 자주 등장하는 문자가 대체로 짧은 코드워드를 갖도록 트리를 구성한다.

### 허프만 알고리즘의 탐욕 선택

각 단계에서 빈도가 가장 낮은 두 노드를 선택한다.

두 노드를 자식으로 갖는 새 부모 노드를 만들고, 부모의 빈도를 두 자식의 빈도 합으로 설정한다.

```
빈도가 가장 낮은 두 노드 선택
             ↓
두 노드를 하나의 부모 노드로 결합
             ↓
부모의 빈도 = 두 자식의 빈도 합
             ↓
노드가 하나 남을 때까지 반복
```

처음에는 각 문자 하나가 각각 리프 노드이다.

결합한 부모 노드도 이후 단계에서는 하나의 후보 노드로 취급한다.

마지막으로 남은 노드가 허프만 트리의 루트가 된다.

### 허프만 트리 구성 예제

다음은 강의 자료의 문자별 등장 빈도이다.

빈도는 천 번 단위로 표현한다.

| 문자 | 빈도 f(c) |
|---|---:|
| a | 45 |
| b | 13 |
| c | 12 |
| d | 16 |
| e | 9 |
| f | 5 |
| 합계 | 100 |

즉, a는 45,000번, f는 5,000번 등장한다.

처음에는 빈도가 가장 낮은 두 문자 f와 e를 결합한다.

$$
5+9=14
$$

다음으로 남은 후보 중 빈도가 가장 낮은 c와 b를 결합한다.

$$
12+13=25
$$

이후에도 현재 후보 중 빈도가 가장 낮은 두 노드를 반복해서 결합한다.

| 단계 | 선택한 노드의 빈도 | 새 노드의 빈도 | 결합 후 후보 빈도 |
|---|---|---:|---|
| 초기 | — | — | 5, 9, 12, 13, 16, 45 |
| 1 | 5, 9 | 14 | 12, 13, 14, 16, 45 |
| 2 | 12, 13 | 25 | 14, 16, 25, 45 |
| 3 | 14, 16 | 30 | 25, 30, 45 |
| 4 | 25, 30 | 55 | 45, 55 |
| 5 | 45, 55 | 100 | 100 |

노드 하나가 남았으므로 반복을 종료한다.

각 결합에서 먼저 선택한 노드를 왼쪽에 두면 다음 트리를 얻는다.

```
                    100
                   /   \
                0 /     \ 1
                 a:45    55
                        /  \
                     0 /    \ 1
                      25     30
                     / \    /  \
                  0 /   \1 0/    \1
                   c:12 b:13 14   d:16
                            /  \
                         0 /    \ 1
                          f:5   e:9
```

내부 노드의 숫자는 해당 서브트리에 속한 문자들의 빈도 합이다.

### 코드워드와 부호화 비용

왼쪽 간선에 0, 오른쪽 간선에 1을 부여하면 다음 코드워드를 얻는다.

| 문자 | 빈도 | 코드워드 | 길이 |
|---|---:|---|---:|
| a | 45 | 0 | 1 |
| b | 13 | 101 | 3 |
| c | 12 | 100 | 3 |
| d | 16 | 111 | 3 |
| e | 9 | 1101 | 4 |
| f | 5 | 1100 | 4 |

빈도가 가장 큰 a는 깊이 1에 있고, 코드워드 길이는 1비트이다.

부호화 비용을 계산하면 다음과 같다.

$$
\begin{aligned}
B(T)
&=
45\times1
+13\times3
+12\times3\\
&\quad
+16\times3
+9\times4
+5\times4\\
&=224
\end{aligned}
$$

빈도 단위가 천 번이므로 실제 비용은 다음과 같다.

$$
224{,}000\text{ bits}
$$

같은 100,000개의 문자를 3비트 고정 길이 코드로 표현하면 다음과 같다.

$$
100{,}000\times3=300{,}000\text{ bits}
$$

따라서 허프만 코드를 사용한 문자 데이터의 비트 수는 다음만큼 감소한다.

$$
300{,}000-224{,}000=76{,}000\text{ bits}
$$

감소 비율은 다음과 같다.

$$
\frac{76{,}000}{300{,}000}\times100
\approx25.3\%
$$

이는 코드 트리나 원본 길이 등을 저장하는 추가 비용을 제외한 비교이다.

왼쪽과 오른쪽 자식을 바꾸거나, 빈도가 같은 후보의 선택 순서를 다르게 정하면 코드워드가 달라질 수 있다.

이때도 올바른 허프만 알고리즘으로 구성한 코드라면 전체 부호화 비용은 최적이다.

## 허프만 알고리즘

### 알고리즘

빈도가 가장 낮은 두 노드를 빠르게 찾기 위해 최소 우선순위 큐를 사용한다.

우선순위는 노드의 빈도이다.

```
HUFFMAN(C)
    Q = new min-priority-queue

    for each character c in C
        node = new leaf
        node.character = c
        node.freq = frequency[c]
        insert node into Q

    while Q.size > 1
        x = EXTRACT-MIN(Q)
        y = EXTRACT-MIN(Q)

        z = new internal node
        z.left = x
        z.right = y
        z.freq = x.freq + y.freq

        INSERT(Q, z)

    if Q is empty
        return empty tree

    return EXTRACT-MIN(Q)
```

EXTRACT-MIN은 큐에서 빈도가 가장 작은 노드를 제거하고 반환한다.

처음에 문자 수가 n개라면 한 번 결합할 때마다 큐의 노드 수가 1개씩 줄어든다.

따라서 n ≥ 1일 때 결합 횟수는 다음과 같다.

$$
n-1
$$

처음에는 문자 리프 n개가 있고, 결합할 때마다 내부 노드가 하나씩 추가된다.

따라서 n ≥ 1인 허프만 트리의 전체 노드 수는 다음과 같다.

$$
n+(n-1)=2n-1
$$

### 코드워드 생성

허프만 트리를 만든 뒤 루트에서 리프까지 탐색하면서 코드워드를 생성한다.

왼쪽으로 이동할 때는 0, 오른쪽으로 이동할 때는 1을 경로에 추가한다.

```
GENERATE-CODES(node, path)
    if node is a leaf
        code[node.character] = path
        return

    GENERATE-CODES(node.left, path + "0")
    GENERATE-CODES(node.right, path + "1")
```

전체 트리에 대해서는 루트와 빈 경로로 호출한다.

```
GENERATE-CODES(root, "")
```

예를 들어 앞의 허프만 트리에서 문자 e까지의 경로는 다음과 같다.

```
오른쪽 → 오른쪽 → 왼쪽 → 오른쪽
   1       1       0       1
```

따라서 e의 코드워드는 `1101`이다.

위 의사코드는 경로의 의미를 이해하기 위한 것이다.

실제 구현에서는 경로를 매번 복사하는 대신 하나의 가변 경로에 비트를 추가하고, 재귀 호출이 끝나면 제거할 수 있다.

### 시간 복잡도와 공간 복잡도

문자 수를 n이라고 하고, 최소 우선순위 큐를 이진 최소 힙으로 구현한다고 하자.

처음 n개의 리프를 배열에 만든 뒤 힙으로 구성하면 O(n) 시간이 필요하다.

각 노드를 빈 큐에 하나씩 삽입하는 방식으로 초기화하면 O(n log n) 시간이 걸릴 수 있다.

결합은 n-1번 수행한다.

각 결합에서는 다음 힙 연산을 수행한다.

- 최솟값 두 번 제거
- 새 부모 노드 한 번 삽입

각 힙 연산은 O(log n) 시간이 걸린다.

따라서 n ≥ 2일 때 전체 시간 복잡도는 다음과 같다.

$$
O(n\log n)
$$

n개의 리프와 n-1개의 내부 노드를 저장하므로 트리의 공간은 O(n)이다.

우선순위 큐에도 최대 O(n)개의 노드 참조를 저장한다.

따라서 트리와 큐를 위한 공간은 다음과 같다.

$$
O(n)
$$

코드워드 문자열을 모두 별도로 저장한다면 그 총 길이만큼 추가 공간이 필요하다.

트리가 한쪽으로 길게 치우친 경우 코드워드 길이의 합은 최악의 경우 O(n²)이 될 수 있다.

### 입력과 구현 시 고려할 점

#### 빈 입력

문자가 하나도 없는 입력에서는 트리를 만들지 않고 빈 결과를 반환할 수 있다.

#### 서로 다른 문자가 하나인 입력

문자가 하나뿐이면 트리는 리프 하나로 이루어진다.

루트에서 리프까지 이동한 간선이 없으므로 앞에서 정의한 트리 경로의 길이는 0이다.

다만 실제 비트열을 복원하려면 문자가 몇 번 등장했는지 알아야 한다.

구현 방식에 따라 다음과 같은 규칙을 정할 수 있다.

- 빈 코드워드를 사용하고 원본 문자 수를 별도로 저장한다.
- 해당 문자의 코드워드를 `0`으로 정하고 필요한 횟수만큼 기록한다.

어느 쪽이든 부호화와 복호화가 같은 규칙을 사용해야 한다.

#### 빈도가 같은 경우

빈도가 같은 노드가 있으면 최소 빈도 노드의 선택 순서가 하나로 정해지지 않을 수 있다.

동점 처리나 좌우 자식 배치에 따라 코드워드는 달라질 수 있다.

하지만 서로 다른 허프만 트리라도 주어진 빈도에 대한 전체 부호화 비용은 최적이다.

동일한 결과를 반복해서 얻어야 한다면 문자 번호나 생성 순서 등을 이용하여 동점 처리 규칙을 정할 수 있다.

#### 코드 정보 전달

복호화하려면 사용한 코드워드나 코드 트리를 알아야 한다.

실제 파일 형식에서는 트리, 코드 길이, 원본 데이터 길이 등 복호화에 필요한 정보를 함께 전달할 수 있다.

따라서 실제 압축 결과의 전체 크기는 앞에서 계산한 문자 데이터의 비트 수보다 클 수 있다.

## 허프만 알고리즘의 정당성

허프만 알고리즘이 최적의 이진 접두 코드를 만드는 이유를 두 단계로 살펴본다.

1. 빈도가 가장 낮은 두 문자를 형제로 두는 최적 트리가 존재한다.

2. 두 문자를 하나의 노드로 합친 작은 문제의 최적해를 이용하여 원래 문제의 최적해를 만들 수 있다.

이후 증명에서는 실제로 나타나는 문자의 빈도가 양수이고, 서로 다른 문자가 적어도 두 개라고 가정한다.

### 탐욕 선택 특성

문자 집합 C에서 빈도가 가장 낮은 두 문자를 x와 y라고 하자.

그러면 다음을 만족하는 최적 접두 코드 트리가 적어도 하나 존재한다.

- x와 y는 같은 부모를 가진다.
- 두 문자의 깊이가 같다.
- 코드워드는 마지막 비트만 다르다.

#### 가장 깊은 형제 리프

양의 빈도에 대한 최적 접두 코드 트리는 각 내부 노드가 두 자식을 갖는 형태로 생각할 수 있다.

내부 노드에 자식이 하나뿐이라면 그 노드를 제거하고 자식 서브트리를 위로 올려, 접두 관계를 유지하면서 해당 문자들의 코드 길이를 줄일 수 있기 때문이다.

가장 깊은 리프 하나를 선택하면 그 리프의 형제도 리프이다.

형제가 내부 노드라면 그 아래에 더 깊은 리프가 존재하여 가장 깊다는 조건에 모순된다.

따라서 최적 트리에는 같은 최대 깊이에 있는 형제 리프가 존재한다.

이 형제 리프에 들어 있는 문자를 a와 b라고 하자.

#### 낮은 빈도의 문자를 깊은 위치로 교체

x와 y는 빈도가 가장 낮은 두 문자이므로 a와 b보다 빈도가 높지 않도록 대응시킬 수 있다.

$$
f(x)\le f(a),\qquad f(y)\le f(b)
$$

x와 a의 위치를 서로 바꾼다고 하자.

a는 최대 깊이에 있으므로 다음을 만족한다.

$$
d(a)\ge d(x)
$$

교체 후 비용에서 교체 전 비용을 뺀 값은 다음과 같다.

$$
\begin{aligned}
\Delta B
&=
f(x)d(a)+f(a)d(x)\\
&\quad-\left(f(x)d(x)+f(a)d(a)\right)\\
&=
\left(f(x)-f(a)\right)
\left(d(a)-d(x)\right)\\
&\le 0
\end{aligned}
$$

따라서 빈도가 더 낮은 x를 깊은 위치로 옮겨도 전체 비용은 증가하지 않는다.

같은 방식으로 y도 나머지 가장 깊은 형제 리프의 위치로 옮길 수 있다.

원래 트리가 최적이었으므로, 비용이 증가하지 않은 교체 후의 트리도 최적이다.

따라서 빈도가 가장 낮은 x와 y를 같은 최대 깊이의 형제 리프로 갖는 최적 트리가 존재한다.

두 문자는 같은 부모에서 마지막에 서로 다른 간선을 지나므로 코드워드는 마지막 비트만 다르다.

이 사실이 허프만 알고리즘에서 가장 낮은 빈도의 두 노드를 먼저 결합할 수 있는 근거이다.

### 최적 부분 구조

빈도가 가장 낮은 두 문자 x와 y를 하나의 새 문자 z로 합친다고 하자.

새 문자 집합 C′는 다음과 같다.

$$
C'=(C-\{x,y\})\cup\{z\}
$$

z의 빈도는 두 문자의 빈도 합으로 정의한다.

$$
f(z)=f(x)+f(y)
$$

x와 y가 형제인 트리 T에서 두 리프를 제거하고, 그 부모를 z라는 리프로 바꾸면 작은 문제의 트리 T′를 얻는다.

```text
원래 트리 T:              축소한 트리 T':

      ●                         z
     / \
    x   y
```

z의 깊이를 d라고 하면 원래 트리에서 x와 y의 깊이는 각각 d+1이다.

두 트리의 비용 관계는 다음과 같다.

$$
B(T)=B(T')+f(x)+f(y)
$$

축소된 트리 T′에서 z가 기여하는 비용은 다음과 같다.

$$
\left(f(x)+f(y)\right)d
$$

원래 트리 T에서 x와 y가 기여하는 비용은 다음과 같다.

$$
f(x)(d+1)+f(y)(d+1)
$$

따라서 축소된 문제의 최적 트리 T′가 주어졌을 때, z를 다시 x와 y의 부모로 확장하면 원래 문제의 최적 트리를 얻는다.

만약 확장한 트리보다 비용이 더 낮은 원래 문제의 최적 트리가 있다고 가정하자.

앞의 탐욕 선택 특성에 의해 그 최적 트리는 x와 y를 형제로 갖도록 선택할 수 있다.

그 트리에서 x와 y를 z로 축소하면 비용에서 같은 값 f(x)+f(y)가 빠진다.

그러면 T′보다 더 낮은 비용의 축소 문제 트리를 얻게 되므로 T′가 최적이라는 가정과 모순된다.

따라서 두 최소 빈도 노드를 합친 작은 문제의 최적해를 확장하면 원래 문제의 최적해가 된다.

### 정당성 정리

허프만 알고리즘은 매 단계에서 가장 낮은 빈도의 두 노드를 결합한다.

탐욕 선택 특성에 의해 그 두 노드를 형제로 갖는 최적 트리가 존재한다.

최적 부분 구조에 의해 두 노드를 합친 작은 문제를 최적으로 해결하고 다시 확장하면 원래 문제의 최적 트리를 얻는다.

이 과정을 노드 하나가 남을 때까지 반복하므로 허프만 알고리즘은 주어진 빈도에 대한 최적 이진 접두 코드를 구성한다.

## 힙과 우선순위 큐

허프만 알고리즘은 반복해서 빈도가 가장 작은 두 노드를 선택한다.

이를 효율적으로 수행하기 위해 최소 우선순위 큐를 사용할 수 있다.

이진 힙(Binary Heap)은 우선순위 큐를 구현하는 대표적인 자료구조이다.

### 힙의 구조

이진 힙은 다음 두 조건을 만족하는 이진 트리이다.

1. 트리가 완전 이진 트리의 형태를 유지한다.

2. 부모와 자식 사이에 정해진 힙 속성을 만족한다.

완전 이진 트리는 마지막 레벨을 제외한 모든 레벨이 채워져 있고, 마지막 레벨은 왼쪽부터 빈틈없이 채워진 트리이다.

노드 수가 n일 때 힙의 높이는 다음과 같다.

$$
\lfloor\log_2 n\rfloor
$$

힙은 배열에 순서대로 저장할 수 있다.

배열의 인덱스를 1부터 시작하면 다음 관계를 사용한다.

$$
\operatorname{parent}(i)
=
\left\lfloor\frac{i}{2}\right\rfloor
$$

$$
\operatorname{left}(i)=2i
$$

$$
\operatorname{right}(i)=2i+1
$$

C++의 배열이나 `vector`처럼 인덱스를 0부터 사용하면 다음과 같다.

$$
\operatorname{parent}(i)
=
\left\lfloor\frac{i-1}{2}\right\rfloor
\qquad(i>0)
$$

$$
\operatorname{left}(i)=2i+1
$$

$$
\operatorname{right}(i)=2i+2
$$

계산한 자식 인덱스가 현재 힙의 크기보다 작을 때만 해당 자식이 존재한다.

### 최소 힙과 최대 힙

힙은 부모와 자식의 우선순위 관계에 따라 구분한다.

| 구분 | 부모와 자식의 관계 | 루트 |
|---|---|---|
| 최소 힙 | 부모의 값 ≤ 자식의 값 | 최소값 |
| 최대 힙 | 부모의 값 ≥ 자식의 값 | 최대값 |

허프만 알고리즘에서는 빈도가 가장 낮은 노드를 반복해서 선택하므로 최소 힙이 적합하다.

```
최소 힙의 예:

        5
       / \
      9  12
     / \
   13  16
```

모든 부모가 자식보다 작거나 같으므로 루트가 전체 최소값이다.

단, 힙은 배열 전체가 정렬된 자료구조는 아니다.

형제 노드 사이나 서로 다른 서브트리의 노드 사이에는 별도의 정렬 순서가 보장되지 않는다.

### 힙 속성 유지

노드를 제거하거나 삽입하면 힙 속성이 깨질 수 있다.

최소 힙에서 루트의 최솟값을 제거한 뒤에는 보통 다음 과정을 수행한다.

1. 마지막 노드를 루트 위치로 옮긴다.

2. 두 자식 중 더 작은 자식과 비교한다.

3. 부모가 더 크다면 해당 자식과 교환한다.

4. 힙 속성을 만족하거나 리프에 도달할 때까지 아래로 이동한다.

힙의 높이가 O(log n)이므로 한 번의 아래 방향 복구는 O(log n) 시간에 수행할 수 있다.

새 노드를 삽입할 때는 완전 이진 트리의 마지막 위치에 넣는다.

이후 부모보다 값이 작으면 부모와 교환하면서 위로 이동한다.

이 과정도 최대 힙 높이만큼 이동하므로 O(log n) 시간에 수행할 수 있다.

최대 힙에서도 비교 방향을 반대로 하여 같은 방식으로 속성을 복구한다.

### 힙 구성

정렬되지 않은 배열이 주어져도 아래쪽 내부 노드부터 힙 속성을 복구하여 힙을 만들 수 있다.

이를 상향식 힙 구성(Build Heap)이라고 한다.

모든 노드가 루트만큼 아래로 이동하는 것은 아니다.

대부분의 노드는 트리 아래쪽에 있어 이동할 수 있는 거리가 짧다.

이 점을 이용하면 n개 원소로 힙을 구성하는 시간은 다음과 같다.

$$
O(n)
$$

각 노드를 빈 힙에 하나씩 삽입하는 방법의 O(n log n) 상한보다 더 좋은 결과이다.

허프만 알고리즘에서는 처음 문자 노드들을 한꺼번에 알고 있다면 상향식으로 최소 힙을 구성할 수 있다.

### 힙 정렬

힙 정렬(Heapsort)은 힙의 루트에 최댓값 또는 최솟값이 있다는 성질을 이용하는 정렬 방법이다.

오름차순 정렬을 위해 최대 힙을 사용하는 과정은 다음과 같다.

1. 입력 배열을 최대 힙으로 만든다.

2. 루트의 최댓값과 힙의 마지막 원소를 교환한다.

3. 마지막 원소를 정렬된 영역으로 옮기고 힙의 크기를 1 줄인다.

4. 루트에서 최대 힙 속성을 복구한다.

5. 힙의 크기가 1이 될 때까지 반복한다.

힙 구성에 O(n), 이후 반복 과정에 O(n log n)이 걸리므로 전체 시간 복잡도는 다음과 같다.

$$
O(n\log n)
$$

힙 정렬은 허프만 알고리즘의 필수 단계는 아니다.

허프만 알고리즘에서는 힙을 사용하여 현재 빈도가 가장 낮은 노드를 빠르게 꺼내는 것이 목적이다.

## 정리

부호화는 문자에 비트 문자열을 대응시키는 과정이다.

접두 코드에서는 어떤 코드워드도 다른 코드워드의 접두사가 아니므로, 비트를 앞에서부터 읽으며 코드워드의 경계를 결정할 수 있다.

허프만 알고리즘은 주어진 문자별 빈도에 대해 최적 이진 접두 코드를 구성한다.

| 항목 | 내용 |
|---|---|
| 탐욕 선택 | 빈도가 가장 낮은 두 노드를 결합 |
| 새 노드의 빈도 | 두 자식 노드의 빈도 합 |
| 자료구조 | 최소 우선순위 큐 |
| 반복 횟수 | 문자 n개에 대해 n-1번 |
| 트리 노드 수 | 문자 n개에 대해 2n-1개 |
| 트리 구성 시간 | 이진 최소 힙 사용 시 O(n log n) |
| 트리와 큐 공간 | O(n) |

허프만 알고리즘의 정당성은 다음 두 성질로 설명할 수 있다.

- 가장 낮은 빈도의 두 문자를 형제로 갖는 최적 트리가 존재한다.
- 두 문자를 하나로 합친 부분 문제의 최적 트리를 확장하면 원래 문제의 최적 트리를 얻는다.

강의 예제에서는 문자 데이터만 비교할 때, 3비트 고정 길이 코드의 300,000비트를 허프만 코드의 224,000비트로 줄일 수 있다.
