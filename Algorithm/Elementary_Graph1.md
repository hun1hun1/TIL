## 그래프

그래프(Graph)는 여러 대상과 그 대상 사이의 관계를 표현하는 자료구조이다.

예를 들어 다음과 같은 관계를 그래프로 나타낼 수 있다.

- 도시와 도시를 연결하는 도로
- 사용자와 사용자 사이의 관계
- 선수 과목과 후속 과목의 관계
- 게임 맵의 위치와 이동 가능한 경로

그래프를 탐색하면 특정 위치에서 도달할 수 있는 대상을 찾거나, 최단 경로와 같은 그래프의 구조를 분석할 수 있다.

### 그래프의 정의

그래프 G는 정점 집합 V와 간선 집합 E로 정의한다.

$$
G=(V,E)
$$

- 정점(Vertex): 그래프에서 대상을 나타낸다.
- 간선(Edge): 두 정점 사이의 관계를 나타낸다.

정점은 노드(Node)라고도 한다.

예를 들어 정점과 간선이 다음과 같다고 하자.

$$
V=\{A,B,C,D\}
$$

$$
E=\{\{A,B\},\{A,C\},\{B,D\}\}
$$

이를 무방향 그래프로 나타내면 다음과 같다.

```
    A
   / \
  B   C
  |
  D
```

정점 수와 간선 수는 각각 다음과 같이 나타낸다.

$$
|V|=4,\qquad |E|=3
$$

그래프 알고리즘의 복잡도는 정점 수 |V|와 간선 수 |E|를 함께 사용하여 표현하는 경우가 많다.

### 방향 그래프와 무방향 그래프

간선에 방향이 있는지에 따라 그래프를 구분할 수 있다.

| 구분 | 설명 | 예시 |
|---|---|---|
| 무방향 그래프 | 간선에 방향이 없으며 양쪽 정점의 관계를 나타낸다. | 양방향으로 통행할 수 있는 도로 |
| 방향 그래프 | 간선에 방향이 있으며 출발 정점과 도착 정점을 구분한다. | 일방통행 도로 |

무방향 그래프에서 A와 B를 잇는 간선은 다음과 같이 나타낼 수 있다.

$$
\{A,B\}
$$

방향 그래프에서 A에서 B로 향하는 간선은 순서쌍으로 나타낸다.

$$
(A,B)
$$

방향 그래프에서는 다음 두 간선이 서로 다르다.

$$
(A,B)\ne(B,A)
$$

따라서 A에서 B로 이동할 수 있다고 해서 B에서 A로도 이동할 수 있는 것은 아니다.

무방향 그래프에서 정점 v에 연결된 간선의 수를 차수(Degree)라고 한다.

방향 그래프에서는 들어오는 간선 수를 진입 차수(In-degree), 나가는 간선 수를 진출 차수(Out-degree)라고 구분한다.

### 가중치 그래프

가중치 그래프(Weighted Graph)는 각 간선에 가중치가 부여된 그래프이다.

가중치는 문제에 따라 다음과 같은 값을 나타낼 수 있다.

- 이동 거리
- 이동 시간
- 비용
- 두 지점 사이의 관계 강도

간선의 가중치를 다음 함수로 나타낼 수 있다.

$$
w:E\rightarrow\mathbb{R}
$$

예를 들어 다음 간선의 가중치가 5라면 A에서 B로 이동하는 비용이 5라는 의미로 해석할 수 있다.

$$
w(A,B)=5
$$

어떤 가중치를 허용하는지와 가중치가 무엇을 의미하는지는 문제에서 정한다.

가중치가 있는 그래프라고 해서 모든 최단 경로 알고리즘이 그대로 적용되는 것은 아니다.

### 경로와 거리

경로(Path)는 간선을 따라 이동할 때 거치는 정점들의 순서이다.

예를 들어 다음과 같은 방향 간선이 있다고 하자.

```
A → B → D
```

그러면 A에서 D로 가는 한 경로는 다음과 같다.

```
A, B, D
```

이 경로가 사용하는 간선의 수는 2이다.

시작 정점 s에서 정점 v까지의 거리를 두 정점 사이의 경로에 포함된 최소 간선 수로 정의하면 다음과 같다.

$$
\delta(s,v)
=
\text{s에서 v까지 가는 경로 중 최소 간선 수}
$$

s에서 v로 가는 경로가 없다면 다음과 같이 나타낸다.

$$
\delta(s,v)=\infty
$$

이번에 살펴볼 BFS는 이처럼 간선 수를 기준으로 한 최단 거리를 구한다.

간선마다 이동 비용이 서로 다르다면 최소 간선 수의 경로가 최소 비용 경로라는 보장은 없다.

## 그래프의 표현

알고리즘에서 그래프를 표현하는 대표적인 방법은 다음 두 가지이다.

- 인접 리스트(Adjacency List)
- 인접 행렬(Adjacency Matrix)

표현 방법에 따라 필요한 공간과 수행 연산의 시간이 달라진다.

다음 예제에서는 중복 간선과 자기 자신으로 향하는 간선이 없는 그래프를 사용한다.

### 인접 리스트

인접 리스트는 각 정점에 대해 그 정점과 인접한 정점들의 목록을 저장한다.

무방향 그래프를 생각해 보자.

```
    A
   / \
  B   C
  |
  D
```

인접 리스트는 다음과 같다.

```
A: B, C
B: A, D
C: A
D: B
```

무방향 간선은 양쪽 정점의 인접 리스트에 각각 한 번씩 나타난다.

예를 들어 간선 {A, B}는 다음 두 곳에 저장된다.

```
A의 리스트: B
B의 리스트: A
```

방향 그래프에서는 각 정점에서 나가는 간선의 도착 정점을 저장한다.

```
A → B
```

위 간선은 다음과 같이 저장한다.

```
A: B
```

B의 리스트에는 B에서 A로 가는 간선이 따로 있을 때만 A를 저장한다.

가중치가 있는 경우에는 이웃 정점과 가중치를 함께 저장할 수 있다.

```
A: (B, 5), (C, 2)
```

이는 A에서 B로 가는 간선의 가중치가 5이고, A에서 C로 가는 간선의 가중치가 2라는 뜻이다.

인접 리스트의 전체 공간 복잡도는 다음과 같다.

$$
\Theta(|V|+|E|)
$$

각 정점의 리스트를 위한 공간과 간선 정보를 위한 공간이 필요하다.

한 정점의 인접 리스트를 모두 순회하는 시간은 해당 리스트의 길이에 비례한다.

- 무방향 그래프: 해당 정점의 차수
- 방향 그래프: 해당 정점의 진출 차수

특정 간선이 존재하는지 확인하려면 일반적인 인접 리스트에서는 해당 리스트를 순회해야 한다.

따라서 정점 u의 인접 리스트 길이를 deg(u)라고 하면 확인 시간은 최악의 경우 다음과 같다.

$$
O(\operatorname{deg}(u)+1)
$$

### 인접 행렬

인접 행렬은 정점 수가 |V|인 그래프를 |V| × |V| 크기의 행렬로 나타낸다.

행렬 A를 다음과 같이 정의한다.

$$
A[i,j]=
\begin{cases}
1
& \text{if 정점 }i\text{에서 정점 }j\text{로 가는 간선이 존재}, \\[4pt]
0
& \text{otherwise}.
\end{cases}
$$

앞의 무방향 그래프를 정점 순서 A, B, C, D로 표현하면 다음과 같다.

| 정점 | A | B | C | D |
|---|---:|---:|---:|---:|
| A | 0 | 1 | 1 | 0 |
| B | 1 | 0 | 0 | 1 |
| C | 1 | 0 | 0 | 0 |
| D | 0 | 1 | 0 | 0 |

무방향 간선은 양방향 관계를 나타내므로 인접 행렬은 대각선을 기준으로 대칭이다.

$$
A[i,j]=A[j,i]
$$

방향 그래프에서는 일반적으로 이 대칭 관계가 성립하지 않는다.

가중치 그래프라면 간선이 존재하는 위치에 해당 가중치를 저장할 수 있다.

이때 가중치 0도 유효할 수 있으므로, 간선이 없다는 뜻으로 0을 무조건 사용해서는 안 된다.

간선의 존재 여부를 별도로 저장하거나, 문제에 맞는 다른 표시를 사용할 수 있다.

인접 행렬의 공간 복잡도는 다음과 같다.

$$
\Theta(|V|^2)
$$

두 정점 사이의 간선 존재 여부는 해당 행과 열을 바로 확인할 수 있으므로 Θ(1) 시간에 알 수 있다.

반면 한 정점의 모든 이웃을 찾으려면 해당 행의 모든 열을 확인해야 하므로 Θ(|V|) 시간이 걸린다.

### 두 표현의 비교

| 항목 | 인접 리스트 | 인접 행렬 |
|---|---|---|
| 공간 | Θ(\|V\| + \|E\|) | Θ(\|V\|²) |
| 정점 u의 모든 이웃 순회 | Θ(deg(u) + 1) | Θ(\|V\|) |
| 간선 (u, v) 존재 여부 | 최악의 경우 O(deg(u) + 1) | Θ(1) |
| 주로 유리한 경우 | 간선이 적은 희소 그래프 | 간선이 많거나 간선 존재 여부를 자주 확인하는 경우 |

방향 그래프에서 위 표의 deg(u)는 정점 u의 진출 차수를 뜻한다.

간선 수가 정점 수의 제곱보다 훨씬 적은 그래프를 희소 그래프(Sparse Graph)라고 한다.

간선이 가능한 수에 가깝게 많은 그래프를 밀집 그래프(Dense Graph)라고 한다.

정점 수뿐 아니라 그래프의 간선 수와 자주 수행하는 연산을 고려하여 표현 방법을 선택해야 한다.

### 정점과 간선의 속성

그래프 알고리즘은 정점과 간선에 추가 정보를 저장할 수 있다.

예를 들어 정점 v에 대해 다음 정보를 사용할 수 있다.

```
v.color: 탐색 상태
v.d: 거리 또는 발견 시간
v.π: 탐색 과정에서 v를 발견한 이전 정점
```

간선에도 가중치와 같은 속성을 저장할 수 있다.

```
(u, v).weight: 간선 (u, v)의 가중치
```

같은 이름의 속성이라도 알고리즘에 따라 의미가 다를 수 있다.

예를 들어 BFS에서 v.d는 시작 정점으로부터의 거리이고, DFS에서 v.d는 발견 시간이다.

## 너비 우선 탐색

너비 우선 탐색(Breadth-First Search, BFS)은 시작 정점에서 가까운 정점부터 차례대로 탐색하는 방법이다.

여기서 가깝다는 것은 시작 정점에서 도달하기까지 필요한 간선 수가 적다는 뜻이다.

### BFS의 동작 방식

시작 정점 s에서 BFS를 수행하면 다음 순서로 정점을 발견한다.

```
거리 0인 정점
      ↓
거리 1인 정점들
      ↓
거리 2인 정점들
      ↓
...
```

거리 k인 모든 정점을 거리 k+1인 정점보다 먼저 발견한다.

이를 위해 먼저 들어온 원소가 먼저 나가는 FIFO 큐(Queue)를 사용한다.

1. 시작 정점을 발견하고 큐에 넣는다.

2. 큐에서 정점을 하나 꺼낸다.

3. 그 정점에서 갈 수 있는 미발견 정점을 발견하고 큐에 넣는다.

4. 큐가 빌 때까지 반복한다.

### 정점의 상태

BFS 진행 상태를 색으로 구분할 수 있다.

| 색 | 의미 |
|---|---|
| WHITE | 아직 발견하지 못한 정점 |
| GRAY | 발견했지만 인접 정점 검사를 마치지 않은 정점 |
| BLACK | 인접 정점 검사를 모두 마친 정점 |

GRAY와 BLACK 정점은 모두 이미 발견된 정점이다.

정점을 처음 발견할 때 GRAY로 바꾸고 큐에 넣는다.

인접 정점 검사를 마치면 BLACK으로 바꾼다.

이렇게 하면 같은 정점을 큐에 여러 번 넣지 않는다.

### BFS 알고리즘

시작 정점 s에서 모든 정점까지의 최소 간선 수를 구한다.

```
BFS(G, s)
    for each vertex u in G.V
        u.color = WHITE
        u.d = ∞
        u.π = NIL

    s.color = GRAY
    s.d = 0

    Q = empty queue
    ENQUEUE(Q, s)

    while Q is not empty
        u = DEQUEUE(Q)

        for each v in G.Adj[u]
            if v.color == WHITE
                v.color = GRAY
                v.d = u.d + 1
                v.π = u

                ENQUEUE(Q, v)

        u.color = BLACK
```

각 속성의 의미는 다음과 같다.

| 속성 | 의미 |
|---|---|
| v.color | 정점 v의 탐색 상태 |
| v.d | 시작 정점에서 v까지의 최소 간선 수 |
| v.π | BFS가 v를 처음 발견할 때 사용한 이전 정점 |

도달하지 못한 정점은 WHITE 상태로 남으며 거리도 ∞이다.

방향 그래프에서는 간선의 방향을 따라 도달할 수 있는 정점만 발견한다.

### BFS 실행 예제

다음 방향 그래프를 사용하자.

```
A → B → D → E
↓       ↑
C ──────┘

D → B

F는 다른 정점과 연결되어 있지 않다.
```

각 정점의 인접 리스트는 다음과 같다.

```
A: B, C
B: D
C: D
D: B, E
E: 없음
F: 없음
```

정점 A에서 시작하고, 각 인접 리스트를 표시된 순서대로 검사한다고 하자.

| 단계 | 큐에서 꺼낸 정점 | 새로 발견한 정점 | 처리 후 큐 |
|---|---|---|---|
| 초기 | — | A | A |
| 1 | A | B, C | B, C |
| 2 | B | D | C, D |
| 3 | C | 없음 | D |
| 4 | D | E | E |
| 5 | E | 없음 | 빈 큐 |

C에서 D로 가는 간선도 있지만, D는 이미 B를 통해 발견되었다.

D에서 B로 가는 간선 역시 B가 이미 발견된 상태이므로 B를 다시 큐에 넣지 않는다.

최종 결과는 다음과 같다.

| 정점 | 거리 d | 이전 정점 π |
|---|---:|---|
| A | 0 | NIL |
| B | 1 | A |
| C | 1 | A |
| D | 2 | B |
| E | 3 | D |
| F | ∞ | NIL |

F는 A에서 도달할 수 없으므로 발견되지 않는다.

발견된 정점들의 이전 정점을 연결하면 다음 BFS 트리를 얻는다.

```
A
├─ B
│  └─ D
│     └─ E
└─ C
```

A에서 D까지는 `A → B → D`와 `A → C → D`라는 두 최단 경로가 있다.

위 실행에서는 B를 먼저 검사했으므로 D의 이전 정점이 B가 된다.

인접 리스트의 순서가 달라지면 선택되는 최단 경로는 달라질 수 있지만, BFS가 구하는 최단 거리는 변하지 않는다.

### 최단 경로의 복원

BFS가 저장한 이전 정점 π를 따라가면 시작 정점부터 목표 정점까지의 경로를 복원할 수 있다.

```
PRINT-PATH(s, v)
    if v == s
        print s
    else if v.π == NIL
        print "경로 없음"
    else
        PRINT-PATH(s, v.π)
        print v
```

A에서 E까지 복원하면 다음과 같다.

```
E.π = D
D.π = B
B.π = A
```

이전 정점을 거꾸로 따라간 결과를 원래 순서로 정리하면 다음 경로를 얻는다.

```
A → B → D → E
```

간선 수는 3이므로 E의 거리와 같다.

목표 정점이 시작 정점과 다르고 이전 정점이 NIL이면, 해당 BFS에서 목표 정점에 도달하지 못한 것이다.

### 시간 복잡도와 공간 복잡도

그래프를 인접 리스트로 표현했다고 하자.

- 모든 정점의 속성을 초기화하는 데 O(|V|) 시간이 걸린다.
- 각 정점은 최대 한 번 큐에 들어간다.
- 각 정점의 인접 리스트는 해당 정점을 큐에서 꺼낼 때 한 번 검사한다.

방향 간선은 시작 정점이 처리될 때 최대 한 번 검사한다.

무방향 간선은 양쪽 정점의 인접 리스트에 있으므로 최대 두 번 검사한다.

따라서 시간 복잡도는 다음과 같다.

$$
O(|V|+|E|)
$$

시작 정점에서 모든 정점에 도달하지 못하면 도달하지 못한 정점들의 인접 리스트는 검사하지 않는다.

다만 위 알고리즘은 처음에 모든 정점의 속성을 초기화한다.

거리, 이전 정점, 상태와 큐에 필요한 추가 공간은 다음과 같다.

$$
O(|V|)
$$

이는 그래프 자체를 저장하는 공간을 제외한 값이다.

인접 행렬을 사용하면 도달한 정점마다 행 전체를 확인해야 하므로 최악의 경우 탐색에 O(|V|²) 시간이 걸린다.

## 깊이 우선 탐색

깊이 우선 탐색(Depth-First Search, DFS)은 가능한 한 깊이 들어간 뒤, 더 이상 진행할 수 없으면 이전 정점으로 돌아와 탐색을 계속하는 방법이다.

### DFS의 동작 방식

현재 정점에서 아직 발견하지 않은 인접 정점이 있으면 그 정점으로 이동한다.

새 정점에서도 같은 과정을 반복한다.

```
현재 정점 발견
      ↓
미발견 인접 정점으로 이동
      ↓
더 이상 이동할 곳이 없으면 이전 정점으로 복귀
      ↓
남은 인접 정점 검사
```

재귀 함수로 구현하면 함수 호출 스택이 이전 정점으로 돌아가는 과정을 관리한다.

명시적인 스택을 사용하여 반복문으로 구현할 수도 있다.

단, 스택을 이용한 구현에서 인접 정점을 처리하는 방식에 따라 재귀 DFS와 방문 순서가 달라질 수 있다.

### 발견 시간과 종료 시간

DFS에서는 각 정점에 두 시각을 기록할 수 있다.

| 속성 | 의미 |
|---|---|
| v.d | 정점 v를 처음 발견한 시간 |
| v.f | 정점 v의 인접 정점 검사를 마친 종료 시간 |
| v.π | 정점 v를 처음 발견한 이전 정점 |

정점을 발견하거나 종료할 때마다 전역 시간 time을 1 증가시킨다.

정점 수가 |V|이면 전체 DFS에서 시간은 1부터 2|V|까지 한 번씩 사용된다.

모든 정점 v에 대해 다음이 성립한다.

$$
1\le v.d<v.f\le 2|V|
$$

BFS와 마찬가지로 탐색 상태를 색으로 구분한다.

| 색 | DFS에서의 의미 |
|---|---|
| WHITE | 아직 발견하지 않은 정점 |
| GRAY | 발견했지만 탐색을 마치지 않은 정점 |
| BLACK | 인접 정점 검사를 모두 마친 정점 |

### DFS 알고리즘

전체 DFS는 특정 시작 정점 하나만 탐색하지 않는다.

아직 발견되지 않은 정점이 남아 있다면 그 정점에서 새로운 탐색을 시작한다.

```
DFS(G)
    for each vertex u in G.V
        u.color = WHITE
        u.π = NIL

    time = 0

    for each vertex u in G.V
        if u.color == WHITE
            DFS-VISIT(G, u)
```

한 정점에서 시작하는 재귀 탐색은 다음과 같다.

```
DFS-VISIT(G, u)
    time = time + 1
    u.d = time
    u.color = GRAY

    for each v in G.Adj[u]
        if v.color == WHITE
            v.π = u
            DFS-VISIT(G, v)

    u.color = BLACK
    time = time + 1
    u.f = time
```

time은 모든 DFS-VISIT 호출에서 공유하는 값이다.

한 정점에서 도달할 수 있는 부분만 탐색하려면 해당 정점에 대해 DFS-VISIT을 한 번 호출할 수도 있다.

이 경우 전체 정점에 대한 바깥 반복문을 수행하는 DFS와 구분해야 한다.

### DFS 실행 예제

앞의 방향 그래프를 다시 사용한다.

```
A: B, C
B: D
C: D
D: B, E
E: 없음
F: 없음
```

전체 DFS의 정점 검사 순서는 A, B, C, D, E, F라고 하자.

각 인접 리스트도 표시된 순서대로 검사한다.

탐색은 다음 순서로 진행된다.

```
A 발견
└─ B 발견
   └─ D 발견
      ├─ B는 이미 발견된 상태
      └─ E 발견
         └─ E 종료

      D 종료
   B 종료

└─ C 발견
   └─ D는 이미 종료된 상태

   C 종료

A 종료

F 발견
F 종료
```

결과는 다음과 같다.

| 정점 | 발견 시간 d | 종료 시간 f | 이전 정점 π |
|---|---:|---:|---|
| A | 1 | 10 | NIL |
| B | 2 | 7 | A |
| C | 8 | 9 | A |
| D | 3 | 6 | B |
| E | 4 | 5 | D |
| F | 11 | 12 | NIL |

A에서 시작한 탐색으로 A, B, C, D, E를 발견한다.

F는 그 탐색에서 발견되지 않았으므로 전체 DFS의 바깥 반복문이 F를 새로운 시작 정점으로 선택한다.

### 시간 복잡도와 공간 복잡도

인접 리스트를 사용하여 전체 DFS를 수행한다고 하자.

각 정점은 한 번 발견되고 한 번 종료된다.

또한 각 정점의 인접 리스트를 한 번씩 검사한다.

따라서 전체 시간 복잡도는 다음과 같다.

$$
\Theta(|V|+|E|)
$$

전체 DFS는 도달하지 못한 정점에서도 새로운 탐색을 시작하므로 모든 정점과 간선을 검사한다.

상태, 시간, 이전 정점 정보를 위한 추가 공간은 O(|V|)이다.

재귀 호출 스택도 최악의 경우 정점 수에 비례한다.

$$
O(|V|)
$$

이는 그래프 자체의 저장 공간을 제외한 값이다.

인접 행렬을 사용하면 각 정점의 행을 검사하므로 전체 DFS는 Θ(|V|²) 시간이 걸린다.

정점이 매우 많은 그래프에서 재귀 DFS를 사용하면 호출 스택이 깊어질 수 있다.

구현 환경에 따라 명시적인 스택을 사용하는 반복 DFS를 고려할 수 있다.

## DFS의 성질

### 깊이 우선 포리스트

전체 DFS는 미발견 정점이 남아 있을 때마다 새로운 시작 정점에서 탐색한다.

각 시작 정점에서 발견한 정점들과 발견에 사용한 간선들은 하나의 깊이 우선 트리(Depth-First Tree)를 이룬다.

이 트리들의 집합을 깊이 우선 포리스트(Depth-First Forest)라고 한다.

앞의 예제에서는 다음 두 트리가 만들어진다.

```
첫 번째 트리:       두 번째 트리:

A                   F
├─ B
│  └─ D
│     └─ E
└─ C
```

정점 v의 이전 정점이 u라면 간선 (u, v)는 DFS가 v를 처음 발견하는 데 사용한 간선이다.

이전 정점이 NIL인 정점은 해당 DFS 트리의 루트이다.

방향 그래프에서는 하나의 DFS 트리에 속하는지가 간선 방향과 정점 검사 순서에 영향을 받는다.

따라서 DFS 트리의 개수를 방향 그래프의 강한 연결 요소 개수와 같다고 볼 수는 없다.

### 발견 시간과 종료 시간의 괄호 구조

각 정점의 발견과 종료를 여는 괄호와 닫는 괄호처럼 볼 수 있다.

앞의 예제에서 발견과 종료 순서는 다음과 같다.

```text
A 발견
  B 발견
    D 발견
      E 발견
      E 종료
    D 종료
  B 종료

  C 발견
  C 종료
A 종료

F 발견
F 종료
```

각 정점의 탐색 구간을 다음과 같이 나타낸다.

$$
[v.d,v.f]
$$

두 정점 u와 v의 구간은 다음 중 하나이다.

1. 서로 겹치지 않는다.

2. 한 구간이 다른 구간 안에 완전히 포함된다.

예를 들어 D와 E의 구간은 다음과 같다.

$$
D:[3,6],\qquad E:[4,5]
$$

E의 구간이 D의 구간에 포함된다.

이는 E가 DFS 트리에서 D의 후손임을 나타낸다.

반면 B와 C의 구간은 서로 겹치지 않는다.

$$
B:[2,7],\qquad C:[8,9]
$$

두 정점 중 어느 쪽도 다른 쪽의 조상이 아니다.

### 간선의 분류

방향 그래프의 DFS에서는 간선을 DFS 포리스트의 구조에 따라 분류할 수 있다.

| 종류 | 설명 |
|---|---|
| 트리 간선(Tree Edge) | DFS가 미발견 정점을 처음 발견할 때 사용한 간선 |
| 역방향 간선(Back Edge) | 정점에서 DFS 트리의 조상으로 향하는 간선 |
| 순방향 간선(Forward Edge) | 조상에서 후손으로 향하지만 트리 간선은 아닌 간선 |
| 교차 간선(Cross Edge) | 위 세 종류에 속하지 않는 간선 |

자기 자신을 향하는 간선은 역방향 간선으로 분류한다.

앞의 예제에서 각 간선의 분류는 다음과 같다.

| 간선 | 종류 | 이유 |
|---|---|---|
| A → B | 트리 간선 | A가 B를 처음 발견한다. |
| A → C | 트리 간선 | A가 C를 처음 발견한다. |
| B → D | 트리 간선 | B가 D를 처음 발견한다. |
| C → D | 교차 간선 | C와 D는 서로 조상과 후손이 아니다. |
| D → B | 역방향 간선 | B는 DFS 트리에서 D의 조상이다. |
| D → E | 트리 간선 | D가 E를 처음 발견한다. |

이 예제에는 순방향 간선이 없다.

예를 들어 그래프에 A → D 간선을 추가하고, DFS가 B를 통해 먼저 D를 발견한다면 A → D는 조상 A에서 후손 D로 향하는 순방향 간선이 된다.

간선 분류는 DFS의 정점 검사 순서와 인접 정점 검사 순서에 따라 달라질 수 있다.

무방향 그래프의 DFS에서는 간선을 트리 간선과 역방향 간선으로 분류한다.

무방향 간선은 인접 리스트에 양쪽 방향으로 나타나므로, 구현에서 부모로 돌아가는 간선의 처리에도 주의해야 한다.

## BFS와 DFS의 비교

| 항목 | BFS | DFS |
|---|---|---|
| 기본 전략 | 시작점에서 가까운 정점부터 탐색 | 가능한 한 깊이 들어간 뒤 되돌아옴 |
| 주로 사용하는 구조 | 큐 | 재귀 호출 스택 또는 명시적 스택 |
| 기록할 수 있는 정보 | 시작점으로부터의 거리, 이전 정점 | 발견 시간, 종료 시간, 이전 정점 |
| 탐색 결과 | 시작점에서 도달 가능한 정점들의 BFS 트리 | 전체 DFS에서는 하나 이상의 DFS 트리 |
| 대표적인 활용 | 간선 수 기준 최단 경로 | 그래프 구조 분석, 위상 정렬, 강한 연결 요소 |
| 인접 리스트 시간 | O(\|V\| + \|E\|) | 전체 DFS에서 Θ(\|V\| + \|E\|) |

BFS는 가중치가 없는 그래프에서 시작 정점으로부터 최소 간선 수를 구한다.

모든 간선의 비용이 같은 경우에도 최소 간선 수 경로는 최소 비용 경로가 된다.

DFS는 깊이 방향으로 탐색하므로, 처음 발견한 경로가 최단 경로라는 보장은 없다.

위상 정렬과 강한 연결 요소는 DFS의 탐색 순서와 종료 시간 등을 활용하는 응용이다.

## 정리

그래프는 정점과 간선으로 대상과 관계를 표현한다.

인접 리스트와 인접 행렬은 각각 공간 사용량과 간선 확인 시간에 차이가 있다.

- 인접 리스트는 간선이 적은 그래프에서 공간을 절약하기 좋다.
- 인접 행렬은 두 정점 사이의 간선 존재 여부를 빠르게 확인할 수 있다.

BFS는 큐를 사용하여 시작 정점에서 가까운 정점부터 탐색한다.

이를 이용하면 시작 정점에서 도달 가능한 각 정점까지의 최소 간선 수와 최단 경로 하나를 구할 수 있다.

DFS는 가능한 한 깊이 탐색하고 되돌아오는 과정을 반복한다.

전체 DFS는 모든 정점을 검사하면서 하나 이상의 트리로 이루어진 깊이 우선 포리스트를 만든다.

DFS의 발견 시간과 종료 시간은 괄호 구조를 이루며, 간선을 트리 간선·역방향 간선·순방향 간선·교차 간선으로 분석하는 데 활용할 수 있다.
