# Basic_Concepts

## 목차

## 알고리즘이란?

알고리즘은 특정 문제를 해결하거나 작업을 수행하기 위한 유한한 명령어들의 집합이다. 모든 알고리즘은 아래 기준을 반드시 만족해야 한다.

1. 입력: 알고리즘은 외부로부터 제공되는 0개 이상의 데이터를 입력으로 받을 수 있다.

2. 출력: 알고리즘의 실행 결과로 하나 이상의 결과값이 생성되어야 한다.

3. 명확성: 각각의 명령은 분명하고 모호하지 않아야 한다.

4. 유한성: 알고리즘은 어떤 입력에 대해서도 실행 과정을 따라갔을 때, 유한한 단계 안에 반드시 종료되어야 한다.

5. 실행 가능성: 알고리즘의 모든 명령은 사람이 연필과 종이만으로도 수행할 수 있을 정도로 명확하고 기본적인 단계로 구성되어야 한다.

## 데이터 추상화

자료형(Data Type)은 데이터 값들의 집합과 그 데이터들에 적용할 수 있는 연산들의 집합으로 정의된다.

추상 자료형(Abstract Data Type)은 데이터와 그 데이터를 다룰 수 있는 연산을 정의하지만, 데이터의 묘사나 연산의 내부 구현은 정의하지 않는 자료형이다.

1. Creator/Constructor(생성자): 새로운 ADT 객체를 생성하는 연산이다.

2. Transformer(변형자): 기존 데이터를 수정하여 ADT 객체를 생성하는 연산이다.

3. Observers/Reporters(관찰자): 객체를 변경하지 않고 정보만 반환하는 연산이다.

## 성능 분석

프로그램의 공간 복잡도(Space Complexity)는 프로그램이 완전히 종료되기까지 필요로 하는 메모리의 양이다.

프로그램의 시간 복잡도(Time Complexity)는 프로그램이 완전히 종료되기까지 필요로 하는 컴퓨터 실행 시간의 양이다.

### 빅오(Big "oh") 표기법

> **Big "oh"**\
> f(n) = O(g(n)) iff(if and only if) there exist positive constants c and n<sub>0</sub> such that f(n) <= cg(n) for all n, n>= n<sub>0</sub>.

빅오 표기법은 알고리즘의 입력 크기에 따른 수행 시간 증가율을 표현하는 방법이다. 빅오 표기법은 보통 최악의 경우(Worst Case)를 표현한다. 즉 f(n)의 upper bound(상한).

빅오 표기법 외에도 빅오메가, 빅세타 표현법도 있다. 빅오메가는 lower bound(하한)을 나타내고 빅세타는 하한과 상한을 동시에 나타낸다. 일반적으로 성능이 얼마나 나쁜지가 중요하므로 상한을 나타내는 빅오 표기법을 많이 사용한다.

빅오 표기법은 상수를 제거하고 입력 크기가 증가함에 따라 증가하는 수행 시간을 분석한다. 예를 들어, 수행 시간이 1000n인 알고리즘과 0.1n<sup>2</sup>인 알고리즘이 있다고 가정해보자. n이 1일 때는 1000n인 알고리즘이 수행시간이 더 오래걸린다. 하지만 n이 증가할수록 격차가 줄어들고 결국에는 0.1n<sup>2</sup>인 알고리즘이 더 오래걸리게 된다. 즉 빅오 표기법은 입력 크기가 커질수록 증가하는 수행 시간의 성장률을 비교하기 위한 방법으로 적합하다.
