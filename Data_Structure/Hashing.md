## 해싱(Hashing)이란?

해싱(Hashing)은 키(Key)를 해시 함수로 변환하여, 데이터를 저장하거나 찾을 위치를 결정하는 기법이다.\
자료구조에서는 데이터를 빠르게 삽입·검색·삭제하는 해시 테이블(Hash Table)을 구현할 때 사용한다.

해싱은 모든 항목을 순서대로 비교하는 대신, 키로 저장 위치를 계산하여 탐색 범위를 줄이는 방식이다.

### 해시 테이블의 구성

해시 테이블은 데이터를 저장하는 버킷(Bucket)들로 구성된다.\
버킷 하나가 여러 슬롯(Slot)을 가질 수 있으며, 슬롯 하나에 항목 하나를 저장한다.

- 사용 기호
    - b: 버킷 수
    - s: 버킷 하나의 슬롯 수
    - n: 저장된 항목 수
    - T: 가능한 전체 키의 수
    - h(k): 키 k의 홈 버킷 번호

전체 슬롯 수는 (b * s)이다.

홈 주소(Home Address)는 해시 함수가 계산한 원래의 저장 위치이다. 충돌 처리 방법에 따라 실제 저장 위치는 홈 주소와 달라질 수 있다.

### 해시 함수

해시 함수(Hash Function)는 키를 저장 위치로 변환하는 함수이다.

좋은 해시 함수는 다음 조건을 갖추어야 한다.
- 같은 키에 대해 일관된 결과를 반환해야 한다.
- 계산 비용이 적어야 한다.
- 키를 여러 버킷에 고르게 분산해야 한다.

해시 값이 같다고 실제 키까지 같은 것은 아니다.

#### 균등 해시 함수

키가 무작위로 선택될 때 각 버킷으로 연결될 확률이 동일한 함수를 균등 해시 함수(Uniform Hash Function)라고 한다.

버킷이 b개라면 이상적인 확률은 다음과 같다.
> P(h(k) = i) = 1/b

일부 버킷에 항목이 집중되면 충돌과 검색 비용이 증가한다.

#### 대표적인 해시 함수

- 제산법(Division): h(k) = k % D
    - 간단하지만 제수 D와 키의 분포에 영향을 받는다.
- 중간 제곱법(Mid-Square): 키를 제곱한 결과의 가운데 비트 일부를 사용
    - 키의 여러 비트가 결과에 반영되도록 한다.
- 접기법(Folding): 키를 여러 부분으로 나누어 합산
    - 부분을 그대로 더하거나 일부를 뒤집어서 더한다.

제산법에서는 키의 규칙과 제수의 관계 때문에 분포가 치우칠 수 있다.\
이러한 편향을 줄이기 위해 소수 등을 제수로 선택할 수 있다.

### 충돌과 오버플로

충돌(Collision)은 새 항목의 홈 버킷에 이미 다른 항목이 있는 상황이다.\
오버플로(Overflow)는 홈 버킷의 슬롯이 모두 차서 새 항목을 저장할 수 없는 상황이다.

버킷당 슬롯이 하나라면 충돌과 오버플로가 동시에 발생한다.

충돌을 완전히 없애기 어려우므로, 해시 테이블에는 다른 저장 위치를 찾거나 같은 버킷에 여러 항목을 연결하는 처리 방법이 필요하다.

오버플로를 처리하는 대표적인 방법은 개방 주소법과 체이닝이 있다.

### 개방 주소법(Open Addressing)

개방 주소법(Open Addressing)은 홈 버킷에 저장할 수 없을 때, 정해진 탐사 규칙으로 다른 빈 위치를 찾아 저장하는 방식이다.

#### 선형 탐사

선형 탐사(Linear Probing)은 다음 버킷을 차례대로 확인한다.

버킷이 13개이고 홈 주소가 12라면 12 -> 0 -> 1 -> 2 -> ... 순서로 탐사한다.

구현은 간단하지만, 항목이 연속된 구간에 모이는 군집화가 발생하여 탐사 횟수가 증가할 수 있다.

#### 제곱 탐사

제곱 탐사(Quadratic Probing)는 탐사 횟수의 제곱을 이용하여 위치를 결정한다.
> h(k)\
> (h(k) + i<sup>2</sup>) % b\
> (h(k) - i<sup>2</sup>) % b

여러 해시 함수를 사용하는 탐사도 가능하다.

### 체이닝(Chaining)

같은 홈 버킷을 갖는 항목들을 연결 리스트 등의 자료구조에 저장하는 방식이다.

개방 조사법과 달리 다른 홈 버킷에 속한 항목까지 탐사할 필요가 없다. 대신 연결 정보 등의 추가 메모리가 필요하며, 한 버킷에 항목이 집중되면 검색 시간이 길어진다.

### 해싱의 시간 복잡도

해시 계산과 키 비교를 상수 시간으로 보는 경우 시간 복잡도는 검색, 삽입, 삭제 모두 평균적으로 O(1), 최악의 경우 O(n)이 된다.

충돌이 한 버킷에 집중되면 많은 항목을 비교해야 하므로 해싱이 항상 O(1)을 보장하지 않는다.

체이닝의 리스트 대신 균형 탐색 트리를 사용하면 최악의 검색 비교 횟수를 O(log n)으로 줄일 수 있다.
